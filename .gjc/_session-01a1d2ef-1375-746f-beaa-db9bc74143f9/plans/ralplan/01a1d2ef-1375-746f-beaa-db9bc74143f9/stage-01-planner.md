# R1 Plan — 등대지기 곰 (Planner stage 1)

## 1. Goal / Non-goals
**Goal (one sentence):** 맵 위에서 캐릭터(곰)가 한 칸씩 움직인다.

Non-goals (GAME_DESIGN.md 기준; 아래는 task로 등장하지 않는다):
- 규칙 전반: 제한시간·기절·갈매기·충돌·점등(스페이스바)·승리·실패·맵 순서 (2장, R2)
- 화면 흐름, 엔딩, 재시작 (3장, R2)
- 갈매기·등불 스프라이트 (4장 R2, "아직 안 정한 것" R2)
- HUD 내용 (R2). 화면 아래 32 px 영역은 2장 표대로 크기만 존재, 내용 없음
- 레벨 2·3 격자 (5장, R3), 사운드·UI 텍스트 (7장, R3), 기술 스펙 확정 (8장, R3)
- 9장 수용 기준 전체 (R2). R1은 아래 3장의 임시 완료 문장만 사용
- 10장 범위 밖 전부, 인터뷰에서 다루지 않은 기능 일체

## 2. RALPLAN-DR
**Principles**
1. 기획서가 유일한 기준. 애매하면 기획서를 먼저 고치고 사람에게 보여준 뒤 코드 (AGENTS.md).
2. goal 하나 = 커밋 하나. 이번 goal은 "한 칸 이동" 하나뿐.
3. 숫자는 기획서에서만 (100 ms, 32 px, 9x7, 352x320). 코드에서 바꾸지 않는다.
4. logic.js는 순수 함수, canvas 무지. 맵·스프라이트는 데이터로 분리.
5. 완료는 테스트가 아니라 사람의 브라우저 확인.

**Decision Drivers (top 3)**
1. 4·5·6장이 비어 있어 코드가 근거 없이 값을 지어내게 될 위험 (AGENTS.md 금지).
2. R1 이동이 R2·R3 미결 항목(키 반복, 100 ms 의미, 렌더링 방식)을 불가피하게 건드림.
3. 사람의 확인 비용 최소화: 문서 검토 1회 + 브라우저 확인 1회.

**Viable Options**
- A. design-v1 커밋(문서만) → 사람 검토 → goal-1 커밋(코드). 장점: AGENTS.md 규칙 그대로, 되돌리기 쉬움, 문서/코드 변경 분리. 단점: 사람 정지점 1개 추가.
- B. 가정 두고 코드 먼저, 문서는 사후 보정. 장점: 빠름. 단점: AGENTS.md 직접 위반("문서 먼저"), 지어낸 값이 고착됨.
- C. design 수정과 코드를 한 커밋에. 장점: 커밋 수 감소. 단점: "goal 하나에 하나"·"design-vN:" 메시지 규칙과 충돌, 검토 대상 혼재.

**Chosen: A.** B는 규칙 위반, C는 커밋 규약과 검토 분리를 깨므로 기각.

## 3. Completion condition (사람이 브라우저에서 확인)
index.html을 브라우저로 열어 아래를 눈으로 확인한다. (design-v1에서 확정한 값 기준)
1. 화면이 352 × 320 px 크기로 보이고 맵이 그 안에 그려진다. (2장 이동 규칙 표 "화면 크기")
2. 맵은 가로 9칸 × 세로 7칸이고 한 칸은 32 × 32 px로 보인다. (2장 "맵 칸 수", "타일 크기")
3. 바깥 테두리는 벽, 안쪽은 바닥이며 곰이 B 위치(왼쪽 위 안쪽 칸)에 서 있다. (5장 레벨 1 격자, 4장 곰·바닥·벽)
4. 방향키 상·하·좌·우를 한 번 누르면 곰이 해당 방향으로 정확히 한 칸 이동한다. 두 칸 이상, 반 칸 위치에 멈추지 않는다. (2장 "방향키 조작")
5. 한 칸 이동은 눈에 띄게 순식간(약 0.1초)에 끝난다. (2장 "한 칸 이동 시간" 100 ms)
6. 곰은 화면(맵) 밖으로 나가지 않는다. (2장 "맵 칸 수"; 벽 처리는 열린 항목 O1)
7. 사용한 색이 6장 8색 안에 있다 (곰·바닥·벽이 서로 구분됨). (6장)

**주의:** 테스트 통과는 완료가 아니다. fixture 데이터로 찍은 스크린샷은 증거가 아니다. 완료 보고는 "index.html을 열어 위 번호 N을 보라"로 한다 (AGENTS.md 완료 조건). 9장은 R2에 채워지므로 이 1~7은 R1 한정 임시 기준이며, design-v1에서 9장에 "R1 임시"로 옮겨 적을지는 O7.

## 4. Step plan
### (a) design-v1 (코드 금지, 커밋 `design-v1:`; 확인자: 사람)
GAME_DESIGN.md만 수정한다.
- 4장: 곰·바닥·벽 3종의 역할과 스프라이트(팔레트 인덱스 격자, 크기 32×32 또는 축소 도트 후 배율 — O6). 갈매기·등불은 "R2"로 남김.
- 5장: 레벨 1 격자 9×7을 인터뷰 스펙 "Map Grids Round 13"에서 글자 그대로 복사 (`#` 벽, `.` 바닥, `B` 곰 시작, `L` 등불 자리). 범례에 L 처리 한 줄 (O2). 레벨 2·3은 R3 유지.
- 6장: 8색 hex. R1에서 쓰는 슬롯 명시(배경, 바닥, 벽, 곰 몸, 곰 어두운 부분, 외곽선 등), 나머지 슬롯은 "R2 이후 사용 예약"이라도 8개 전부 hex 확정. 값은 (에이전트 제안)으로 표기 후 사람 확인.
- 2장 이동 규칙 표에 O1·O3·O4·O5의 결정 행 추가, "아직 안 정한 것"에서 해당 항목 제거/이동.
- 문서 버전 v0→v1. **정지점:** 사람이 승인하기 전 goal-1 착수 금지.

### (b) goal-1 (커밋 `goal-1:`) — 파일별
- `index.html`: canvas(352×320) 하나, `<script type="module" src="src/main.js">`. 외부 파일 없음.
- `src/levels.js`: 5장 레벨 1 문자열 배열을 그대로 복사, export. 좌표 별도 기재 금지.
- `src/sprites.js`: 팔레트 8색 hex 배열(6장)과 곰·바닥·벽 인덱스 배열(4장).
- `src/strings.js`: R1은 UI 문구가 없으므로 **만들지 않는다**(7장 R3).
- `src/logic.js` (순수, 입력 상태 불변, 새 상태 반환):
  - `createState(grid)` → `{ grid, bear:{col,row} }` : 격자에서 `B` 찾아 시작 위치 (좌표 하드코딩 금지).
  - `tileAt(grid, col, row)` → 문자 또는 범위 밖이면 `null`.
  - `directionDelta(key)` → `{dc,dr}` 또는 `null` (ArrowUp/Down/Left/Right만).
  - `moveBear(state, key)` → 새 상태. 목적지가 벽(`#`)/범위 밖(O1 결정에 따름)이면 같은 위치.
- `src/main.js` (렌더/입력, canvas 사용): keydown → `moveBear` 호출, 맵을 O5 위치에 32px 타일로 그림, 이동 표현은 O3 결정대로. 기술 스펙(8장)이 R3 미결이므로 최소 구현만, 루프 구조를 "설계"하지 않는다.
- `test/logic.test.js`: `node --test test/`.

## 5. Open items (사람 결정 필요; 결정은 design-v1에 기록)
- **O1 벽에서 멈춤?** 곰이 `#`로 이동 시도. 옵션 ①그 자리에 머문다(이동 무시) ②벽 통과. 결과: ②는 테두리 밖으로 나가 "맵 안" 전제를 깸. **추천 ①.** 편집: 2장(충돌 규칙은 R2이므로 "벽 막힘만 R1"로 한정해 기록).
- **O2 `L` 칸과 등불 스프라이트.** 격자는 승인본 그대로 `L` 유지(변경 금지). 옵션 ①R1에서는 `L`을 바닥으로 그린다(등불 스프라이트 없음, 점등 없음) ②`L` 자리를 비표시 ③`L` 삭제(승인 격자 변경). 결과: ③은 승인된 맵 위반. **추천 ①**, 5장 범례에 "R1에선 바닥으로 표시, 등불 동작·그림은 R2"를 명기. 곰이 `L` 칸에 서는 것은 허용(막지 않음). 편집: 4장·5장.
- **O3 100 ms의 의미.** ①즉시 위치 이동 후 100 ms 입력 쿨다운 ②100 ms 동안 부드러운 보간 애니메이션 ③100 ms 동안은 쿨다운 없이 즉시 이동(숫자 무의미). 결과: ②는 렌더 루프 설계(8장 R3)를 끌어들임. **추천 ①** (논리 위치는 즉시 한 칸, 화면도 즉시, 100 ms 동안 다음 입력 무시). 편집: 2장.
- **O4 키 누르고 있기.** 2장 "아직 안 정한 것" R2 항목이나 이동이 필연적으로 정해야 함. ①keydown 한 번당 한 칸, 브라우저 자동 반복(`event.repeat`)은 무시 ②반복 허용(100 ms마다 한 칸). 결과: ②는 반복 속도 설계 필요. **추천 ①** (2장 "한 번 누르면 한 칸"과 글자 그대로 일치). 편집: 2장, "아직 안 정한 것"에서 해당 줄을 R1 결정으로 이동.
- **O5 맵 배치.** 9×7 = 288×224 px가 352×288 영역 안. ①가로·세로 중앙(좌우 32, 상하 32 여백) ②좌상단 정렬 ③영역 가득 확대(타일 크기 변경 → 금지). 결과: ③은 32 px 규칙 위반. **추천 ①**, 여백색은 6장 배경색. 편집: 2장(표에 "맵 위치" 행).
- **O6 스프라이트 해상도.** ①32×32 인덱스 배열 직접 ②16×16 도트를 2배 확대. 결과: ①은 데이터가 큼(1024개 ×3), ②는 "타일 32 px"와 일관되고 도트 느낌. **추천 ②**, 단 4장에 "16×16, 2배"를 기록. 편집: 4장.
- **O7 R1 완료 기준을 9장 어디에.** 9장은 R2 소관. ①design-v1에서 9장에 "R1 임시 수용 기준" 번호 1~7을 적고 R2가 이어 확장 ②3장 문장을 이 plan에만 둠. 결과: ②는 AGENTS.md("9장 번호로 말한다")와 어긋남. **추천 ①.** 편집: 9장.
- **O8 키 입력 필터 범위(기절 중 입력 무시)는 R2.** R1엔 기절이 없으므로 결정 불필요 — 열지 않는다(명시적 비결정).

## 6. Risks & verification
**Risks**
- 6장 hex가 에이전트 제안뿐 → 사람이 색 확인 못 하면 디자인 기준 부재. 완화: design-v1 검토 때 샘플 확인 요청.
- R1에서 정한 O3·O4가 R2/R3 결정과 충돌 → 완화: "R1 결정, R2에서 재검토 가능"을 문서에 표기, 코드에 상수 한 곳.
- 스프라이트 오타로 곰이 안 보임 → 사람 브라우저 확인(3장 3번)으로만 확정.
- `file://`에서 ES module이 차단될 수 있음 → AGENTS.md의 `python3 -m http.server 8000` 사용.

**사람 확인 방법:** (1) design-v1 단계: GAME_DESIGN.md 4·5·6장과 O1~O7 결정 확인 후 승인. (2) goal-1 단계: `index.html`(필요 시 `python3 -m http.server 8000` 후 http://localhost:8000)을 열고 3장 1~7번을 순서대로 확인: 곰이 왼쪽 위 안쪽 칸에 있음 → → ↓ ← ↑ 각각 한 번씩 눌러 한 칸씩 움직임 → 벽 쪽으로 눌러 더 못 감 → 키를 꾹 눌렀을 때 O4 결정대로 동작.

**자동 검증(보조, 완료 아님):** `node --test test/`.

**막힘 보고(6회 규칙):** 같은 시도를 6번 넘게 반복하지 않는다. 막히면 멈추고 (a)무엇을 시도했는지 (b)실패 증거 (c)막힌 지점의 기획서 장 번호를 보고. 이후는 ralplan에서 재계획.

**Escalation/Handoff:** 4·5·6장 작성 = executor(문서만) → 사람 승인 → critic 검토 → goal-1 = executor. 범위 확장 요구가 나오면 R2 ralplan으로 넘긴다.
