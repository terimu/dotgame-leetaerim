# R1 Plan (revision, stage 2) — 등대지기 곰

## 1. Goal / Non-goals
**Goal (one sentence):** 맵 위에서 캐릭터(곰)가 한 칸씩 움직인다.

Non-goals (아래는 task로 등장하지 않는다):
- 규칙 전반: 제한시간·기절·갈매기·충돌(벽 막힘 제외)·점등(스페이스바)·승리·실패·맵 순서 (2장, R2)
- 화면 흐름, 엔딩, 재시작 (3장, R2)
- 갈매기·등불 스프라이트 (4장 R2, "아직 안 정한 것" R2)
- HUD 내용 (R2). 화면 아래 32 px는 2장 표대로 크기만 존재, 내용 없음
- 레벨 2·3 격자 (5장, R3), 사운드·UI 텍스트 (7장, R3), 기술 스펙 확정 (8장, R3)
- 9장 수용 기준 전체 (R2). R1은 아래 "R1 임시 수용 기준"만 기록
- 10장 범위 밖 전부, 인터뷰에서 다루지 않은 기능 일체

## 2. RALPLAN-DR
**Principles**
1. 기획서가 유일한 기준. 애매하면 기획서를 먼저 고치고 사람에게 보여준 뒤 코드 (AGENTS.md).
2. goal 하나 = 커밋 하나. 이번 goal은 "한 칸 이동" 하나뿐.
3. 숫자는 기획서에서만 (100 ms, 32 px, 9x7, 352x320). 코드에서 바꾸지 않는다.
4. logic.js는 순수 함수, canvas 무지. 맵·스프라이트는 데이터.
5. 완료는 테스트가 아니라 사람의 브라우저 확인.

**Decision Drivers (top 3)**
1. 4·5·6·9장이 비어 있어 코드가 근거 없이 값을 지어낼 위험.
2. R1 이동이 R2·R3 미결 항목(키 반복, 100 ms 의미, 렌더링)을 불가피하게 건드림 → 사용자 결정으로 해소됨.
3. 사람의 확인 비용 최소화: 문서 검토 1회 + 브라우저 확인 1회.

**Viable Options**
- A. design-v1 커밋(문서만) → 사람 검토 → goal-1 커밋(코드). 장점: AGENTS.md 규칙 그대로, 되돌리기 쉬움. 단점: 사람 정지점 1개 추가.
- B. 가정 두고 코드 먼저. 장점: 빠름. 단점: "문서 먼저" 직접 위반, 지어낸 값 고착.
- C. 문서와 코드를 한 커밋에. 장점: 커밋 수 감소. 단점: "goal 하나에 하나"·"design-vN:" 규칙과 충돌, 검토 대상 혼재.

**Chosen: A.** B는 규칙 위반, C는 커밋 규약·검토 분리를 깨므로 기각.

## 3. Intent Reconciliation
사용자가 확정한 4건 (open item에서 제외):
- O1 벽: 곰이 `#`로 이동 시도하면 제자리 유지(이동 무시). R1 2장에는 벽 막힘만 기록, 갈매기 등 충돌은 R2.
- O3 100 ms: 논리·화면 모두 즉시 한 칸 이동 후 100 ms 입력 쿨다운. 보간 애니메이션·렌더 루프 설계 없음 (8장 R3 유지).
- O4 키 누르고 있기: keydown 한 번 = 한 칸. 브라우저 자동 반복(`event.repeat`)은 무시.
- O7 9장: design-v1이 9장에 "R1 임시 수용 기준" 번호 항목을 쓰고 R2가 확장. 완료 보고는 9장 번호를 인용.
유지된 non-goals는 1장과 동일. O8(기절 중 입력)은 R1에 기절이 없으므로 닫힌 채 유지.

## 4. Completion condition + R1 임시 수용 기준 (design-v1이 9장에 그대로 기록)
index.html을 브라우저로 열어 눈으로 확인한다. 아래 1~7이 9장 "R1 임시 수용 기준" 번호다.
1. 화면이 352 × 320 px 크기로 보이고 맵이 그 안에 그려진다. (2장 이동 규칙 표 "화면 크기")
2. 맵은 가로 9칸 × 세로 7칸이고 한 칸은 32 × 32 px로 보인다. (2장 "맵 칸 수", "타일 크기")
3. 바깥 테두리는 벽, 안쪽은 바닥이며 곰이 B 위치(왼쪽 위 안쪽 칸)에 서 있다. (5장 레벨 1 격자, 4장 곰·바닥·벽)
4. 방향키 상·하·좌·우를 한 번 누르면 곰이 해당 방향으로 정확히 한 칸, 순식간에 이동한다(중간 위치에 머물지 않음). 키를 꾹 누르고 있어도 자동 반복으로 추가 이동하지 않고 한 칸만 이동한다. (2장 "방향키 조작", "한 칸 이동 시간" 및 design-v1에 기록되는 키 반복 무시 결정)
5. 한 칸 이동 직후 약 0.1초 동안은 다음 방향키 입력이 무시되고, 그 뒤에는 다시 한 칸 이동한다. (2장 "한 칸 이동 시간" 100 ms, design-v1 기록 쿨다운 결정)
6. 곰이 벽 쪽으로 키를 눌러도 벽 안으로 들어가거나 화면 밖으로 나가지 않고 제자리에 머문다. (2장 "맵 칸 수", 5장 레벨 1 격자 테두리 `#`, design-v1 기록 벽 막힘 결정)
7. 사용한 색이 6장 8색 안에 있고 곰·바닥·벽이 서로 구분된다. (6장, 4장)

**주의:** 테스트 통과는 완료가 아니다. fixture 데이터로 찍은 스크린샷은 증거가 아니다. 모든 완료 보고는 "index.html을 열어 9장 수용 기준 N번을 보라" 형식으로 번호(1~7)를 인용한다 (AGENTS.md 완료 조건).

## 5. Step plan
### (a) design-v1 (코드 금지, 커밋 `design-v1:`; 확인자: 사람)
GAME_DESIGN.md만 수정:
- 4장: 곰·바닥·벽 3종 역할과 스프라이트(16×16 팔레트 인덱스 격자, 2배 확대 — O6 기본값). 갈매기·등불은 "R2"로 남김.
- 5장: 레벨 1 격자 9×7을 인터뷰 스펙 "Map Grids Round 13"에서 글자 그대로 복사(`#` `.` `B` `L`). 범례에 "R1에선 L 칸을 바닥으로 표시, 등불 동작·그림은 R2"(O2 기본값).
- 6장: 8색 hex 확정. R1 사용 슬롯(배경·바닥·벽·곰 등) 명시, 나머지 슬롯도 8개 전부 hex. (에이전트 제안)으로 표기.
- 2장 이동 규칙 표: 결정 행 추가 — 벽 막힘(제자리), 즉시 이동+100 ms 입력 쿨다운, keydown 한 번=한 칸·`event.repeat` 무시, 맵 위치 중앙(좌우·상하 32 px 여백, 여백색=6장 배경색, O5 기본값). "아직 안 정한 것"에서 키 반복 항목은 R1 결정으로 이동.
- 9장: 위 "R1 임시 수용 기준" 1~7 기록 (R2가 확장).
- 문서 v0→v1. **정지점:** 사람이 승인하기 전 goal-1 착수 금지.

### (b) goal-1 (커밋 `goal-1:`) — 파일별
- `index.html`: canvas(352×320) 하나, `<script type="module" src="src/main.js">`.
- `src/levels.js`: 5장 레벨 1 문자열 배열 그대로 복사. 좌표 별도 기재 금지.
- `src/sprites.js`: 팔레트 8색 hex(6장), 곰·바닥·벽 16×16 인덱스 배열(4장).
- `src/strings.js`: R1은 UI 문구 없음 → 만들지 않는다 (7장 R3).
- `src/logic.js` (순수, 입력 불변, 새 상태 반환):
  - `createState(grid)` → `{ grid, bear:{col,row} }`; `B`를 찾아 시작 위치.
  - `tileAt(grid, col, row)` → 문자 또는 범위 밖이면 `null`.
  - `directionDelta(key)` → `{dc,dr}` 또는 `null` (ArrowUp/Down/Left/Right만).
  - `moveBear(state, key)` → 새 상태. 목적지가 `#` 또는 범위 밖이면 같은 위치.
  - `canAcceptMove(lastMoveMs, nowMs, cooldownMs)` → boolean. now - last ≥ cooldown이면 true. (쿨다운 상수 100은 문서 값 그대로 한 곳에 둠.)
- `src/main.js` (canvas·입력): keydown에서 `event.repeat`이면 무시, `canAcceptMove` 통과 시 `moveBear` 후 즉시 다시 그림. 맵을 중앙 오프셋에 32px 타일로 그림. 렌더 루프·보간 설계 없음.
- `test/logic.test.js`: `node --test test/`.

### (c) Tests (기대값은 기획서 숫자·격자에서)
| 테스트 | 기대값 | 근거 |
|---|---|---|
| 레벨 1 격자 9열×7행 | 9, 7 | 2장 "맵 칸 수" |
| `createState` 곰 시작 = 격자의 B 칸 | (1,1) | 5장 격자 (문서 격자에서 직접 셈) |
| 오른쪽 1회 → 한 칸 오른쪽 | (2,1) | 2장 "한 번 누르면 한 칸" |
| 아래 1회 → 한 칸 아래 | (1,2) | 2장 |
| 시작 칸에서 왼쪽 → 제자리(벽) | (1,1) | 5장 테두리 `#` + 벽 막힘 결정 |
| 시작 칸에서 위 → 제자리(벽) | (1,1) | 5장 + 벽 막힘 결정 |
| 오른쪽 끝 안쪽 칸(7,1)에서 오른쪽 → 제자리 | (7,1) | 5장 (9칸 폭, 열 8은 `#`) |
| 방향키 외 키는 이동 없음 | 위치 불변 | 2장 "방향키 상·하·좌·우" |

- `event.repeat` 무시는 main.js의 DOM 이벤트 처리이며 순수 로직에서 코드 미러링 없이 검증할 수 없다 → **사람이 확인** (수용 기준 4번).

## 6. Open items (design-v1 검토 기본값; 사람이 문서 diff에서 확인, 별도 질문 없음)
- **O2 `L` 칸 처리.** 격자는 `L` 그대로(변경 금지). 기본값: R1에선 바닥으로 그림, 등불 그림·동작은 R2. 대안: 비표시(결과: 승인 맵과 시각 불일치) / `L` 삭제(승인 맵 위반 → 금지). 편집: 4·5장.
- **O5 맵 배치.** 9×7 = 288×224 px가 352×288 영역 안. 기본값: 중앙(좌우 32, 상하 32 여백), 여백색 = 6장 배경색. 대안: 좌상단 정렬(결과: 우·하 빈 공간 치우침). 타일 확대는 32 px 규칙 위반으로 금지. 편집: 2장.
- **O6 스프라이트 해상도.** 기본값: 16×16 인덱스 배열을 2배 확대(32 px 타일과 일관, 도트 느낌, 데이터 작음). 대안: 32×32 직접(데이터 1024개×3). 편집: 4장.
- **O8** 기절 중 입력 무시: R1에 기절 없음 → 닫힘, 열지 않는다 (R2).

## 7. Risks & verification
**Risks**
- 6장 hex가 에이전트 제안뿐 → 사람 색 확인 필요. 완화: design-v1 검토 때 확인 요청.
- R1 결정(벽·쿨다운·반복)이 R2·R3와 충돌 가능 → 문서에 "R1 결정, R2에서 재검토 가능" 표기.
- 스프라이트 오타로 곰이 안 보임 → 브라우저 확인(9장 3번)으로만 확정.
- `file://`에서 ES module 차단 가능 → AGENTS.md의 `python3 -m http.server 8000` 사용.

**사람 확인 방법:** (1) design-v1: GAME_DESIGN.md 2·4·5·6·9장 diff와 O2·O5·O6 기본값 확인 후 승인. (2) goal-1: `index.html`(필요 시 `python3 -m http.server 8000` 후 http://localhost:8000)을 열고 9장 수용 기준 1~7번을 순서대로: 곰이 왼쪽 위 안쪽 칸 → → ↓ ← ↑ 각각 한 번씩 눌러 한 칸씩 이동(4) → 키를 꾹 눌러 한 칸만 이동(4) → 빠르게 연타해 약 0.1초 간격으로만 이동(5) → 벽 쪽으로 눌러 제자리(6).

**자동 검증(보조, 완료 아님):** `node --test test/`.

**막힘 보고(6회 규칙):** 같은 시도를 6번 넘게 반복하지 않는다. 막히면 멈추고 (a) 시도한 것 (b) 실패 증거 (c) 막힌 지점의 기획서 장·수용 기준 번호를 보고. 이후는 ralplan에서 재계획.

**Handoff:** 4·5·6·9장 작성 = executor(문서만) → 사람 승인 → critic 검토 → goal-1 = executor. 범위 확장 요구는 R2 ralplan으로.
