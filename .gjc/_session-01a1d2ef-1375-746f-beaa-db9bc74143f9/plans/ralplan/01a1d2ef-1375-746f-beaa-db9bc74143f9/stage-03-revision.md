# R1 Plan (revision, stage 3) — 등대지기 곰

## 1. Goal / Non-goals
**Goal (one sentence):** 맵 위에서 캐릭터(곰)가 한 칸씩 움직인다.

Non-goals (task로 등장하지 않는다):
- 규칙 전반: 제한시간·기절·갈매기·충돌(벽 막힘 제외)·점등(스페이스바)·승리·실패·맵 순서 (2장, R2)
- 화면 흐름·엔딩·재시작 (3장, R2)
- 갈매기·등불 스프라이트 (4장 R2, "아직 안 정한 것" R2)
- HUD 내용 (R2). 아래 32 px 띠는 2장 표대로 크기만 존재, 내용 없음
- 레벨 2·3 격자 (5장, R3), 사운드·UI 텍스트 (7장, R3), 기술 스펙 확정 (8장, R3)
- 9장 수용 기준 전체 (R2). R1은 아래 "R1 임시 수용 기준"만 기록
- 10장 범위 밖 전부, 인터뷰에서 다루지 않은 기능 일체

## 2. RALPLAN-DR
**Principles**
1. 기획서가 유일한 기준. 애매하면 기획서를 먼저 고치고 사람에게 보여준 뒤 코드 (AGENTS.md).
2. goal 하나 = 커밋 하나. 이번 goal은 "한 칸 이동" 하나뿐.
3. 숫자는 기획서에서만 (100 ms, 32 px, 9x7, 352x320). 코드에서 바꾸지 않는다.
4. logic.js는 순수 함수, canvas 무지. 맵·스프라이트는 데이터.
5. 완료는 테스트가 아니라 사람의 브라우저 확인.

**Decision Drivers (top 3)**
1. 4·5·6·9장이 비어 있어 코드가 근거 없이 값을 지어낼 위험.
2. R1 이동이 R2·R3 미결 항목을 건드림 → 사용자 결정 4건으로 해소, 나머지는 design-v1 기본값으로 문서 diff에 노출.
3. 사람의 확인 비용 최소화: 문서 검토 1회 + 브라우저 확인 1회.

**Options**
- **A (선택, 유일하게 AGENTS.md와 양립).** design-v1 커밋(문서만) → critic 검토 → 사람 승인 → goal-1 커밋(코드).
- B. 가정 두고 코드 먼저 — AGENTS.md "문서 먼저" 위반. 완전성을 위해 나열만, 기각.
- C. 문서와 코드 한 커밋 — "goal 하나에 하나"·"design-vN:" 규약 위반. 완전성을 위해 나열만, 기각.

## 3. Intent Reconciliation (사용자 확정 4건; 변경 금지)
- O1 벽: `#`로 이동 시도하면 제자리 유지. R1 2장에는 벽 막힘만 기록, 갈매기 등 충돌은 R2.
- O3 100 ms: 논리·화면 모두 즉시 한 칸 이동 후 100 ms 입력 쿨다운. 보간 애니메이션·렌더 루프 설계 없음 (8장 R3 유지).
- O4 키 누르고 있기: keydown 한 번 = 한 칸. `event.repeat` 무시.
- O7 9장: design-v1이 9장에 "R1 임시 수용 기준" 번호 항목을 쓰고 R2가 확장. 모든 완료 보고는 "9장 수용 기준 N번"을 인용.
- O8(기절 중 입력)은 R1에 기절이 없으므로 닫힌 채 유지.

## 4. R1 임시 수용 기준 (design-v1이 9장에 그대로 기록; 번호 = 9장 수용 기준 N번)
1. 화면(canvas)이 352 × 320 px로 보이고 맵이 그 안에 그려진다. (2장 "화면 크기" 행)
2. 맵은 가로 9칸 × 세로 7칸이고 한 칸은 32 × 32 px 정사각형으로 보인다. (2장 "맵 칸 수"·"타일 크기" 행)
3. 맵 바깥 테두리 한 겹은 벽, 안쪽은 바닥이며, 곰이 왼쪽 위 안쪽 칸(B 위치)에 서 있다. (5장 레벨 1 격자, 4장 곰·바닥·벽)
4. 방향키 상·하·좌·우를 한 번 누르면 곰이 해당 방향으로 정확히 한 칸, 중간 위치 없이 즉시 이동한다. 키를 꾹 눌러도 한 칸만 이동한다. (2장 "방향키 조작" 행, 2장 "이동 후 입력 쿨다운" 결정 행 — keydown 1회=1칸, event.repeat 무시)
5. 서로 다른 방향키 두 개(예: → 와 ↓)를 같은 순간에 동시에 누르면 곰은 정확히 한 칸만 이동한다. 키를 모두 뗀 뒤 다시 누르면 다시 한 칸 이동한다. (2장 "이동 후 입력 쿨다운 | 100 ms" 행)
6. 곰이 벽 쪽으로 키를 눌러도 벽 안으로 들어가거나 화면 밖으로 나가지 않고 제자리에 머문다. (2장 "벽 막힘" 결정 행, 5장 레벨 1 격자 테두리 `#`)
7. 곰·바닥·벽·맵 바깥 여백이 서로 뚜렷이 구분되는 색으로 보인다. (4장, 6장 팔레트)

**주의:** 테스트 통과는 완료가 아니다. fixture 데이터로 찍은 스크린샷은 증거가 아니다. 완료 보고는 "index.html을 열어 9장 수용 기준 N번을 보라" 형식으로 번호를 인용한다 (AGENTS.md 완료 조건).
**검증 범위 명시:** (i) 정확한 100 ms 경계는 `canAcceptMove` 99/100 테스트 + goal-1 diff 검토(main.js가 logic.js에서 export한 단일 상수만 쓰는지)로 덮는다. 브라우저에서 사람이 100 ms를 직접 재지 않는다. (ii) 팔레트 소속(sprites.js의 hex == 6장 hex)은 테스트로 주장하지 않으며 브라우저에서 보이는 항목도 아니다. design-v1·goal-1 diff에서 사람이 hex 텍스트를 눈으로 비교한다.

## 5. Step plan
### (a) design-v1 (코드 금지, 커밋 `design-v1:`, GAME_DESIGN.md만 수정; 확인자: 사람)
- **2장 표 재작성:** 기존 행 "한 칸 이동 시간 | 100 ms | 에이전트 제안"을 "이동 후 입력 쿨다운 | 100 ms | 이동 자체는 즉시, R1 사용자 확정"으로 교체(표가 자기모순이 되지 않게). 아래 결정 행 추가:
  - 벽 막힘: `#`로의 이동은 무시, 제자리 (R1 사용자 확정). 맵 밖 이동도 무시.
  - 입력: keydown 한 번 = 한 칸, `event.repeat` 무시 (R1 사용자 확정). "아직 안 정한 것"의 키 반복 항목은 R1 결정으로 이동.
  - 쿨다운은 곰이 실제로 이동했을 때만 시작(벽에 부딪힘은 시작하지 않음); 첫 입력은 항상 수락(초기 lastMoveMs = `-Infinity`); 경계 포함(now − last ≥ 100이면 수락); 시간원 `performance.now()` 하나; 쿨다운 상수는 `src/logic.js`에서 export, main.js는 import만. (design-v1 기본값, diff에서 확인)
  - 맵 위치: 352×288 맵 영역 안에서 오프셋 (32, 32) px, 여백색 = 6장 배경색 (O5 기본값).
  - 입력 처리(keydown)와 keydown 시 다시 그리기는 "R1 임시 구현; 8장은 R3 소관이며 이를 대체할 수 있음"으로 표기. 8장에는 쓰지 않는다.
- **4장:** 곰·바닥·벽 3종 역할과 스프라이트(16×16 팔레트 인덱스 격자, 2배 확대 — O6 기본값). 갈매기·등불은 "R2".
- **5장:** 레벨 1 격자 9×7을 인터뷰 스펙 "Map Grids Round 13"에서 글자 그대로 복사. 범례 기본값: `L`은 R1에서 걸어 들어갈 수 있고 바닥으로 그린다(등불 그림·동작은 R2); `B` 칸은 곰이 떠난 뒤 바닥으로 그린다 (O2 기본값).
- **6장:** 8색 hex 확정, R1 사용 슬롯(배경·바닥·벽·곰·여백 등) 명시, 8개 전부 hex. (에이전트 제안) 표기.
- **9장:** 위 "R1 임시 수용 기준" 1~7 기록 (R2가 확장).
- 문서 v0→v1. **정지점:** critic 검토 후 사람 승인 전 goal-1 착수 금지.

### (b) goal-1 (커밋 `goal-1:`) — 파일별
- `index.html`: canvas(352×320) 하나, `<script type="module" src="src/main.js">`.
- `src/levels.js`: 5장 레벨 1 문자열 배열 그대로 복사. 좌표 별도 기재 금지.
- `src/sprites.js`: 팔레트 8색 hex(6장), 곰·바닥·벽 16×16 인덱스 배열(4장).
- `src/strings.js`: R1은 UI 문구 없음 → 만들지 않는다 (7장 R3).
- `src/logic.js` (순수, 입력 불변, 새 상태 반환; 상수는 2장 값):
  - `MOVE_COOLDOWN_MS = 100`, `TILE_SIZE = 32`, `SCREEN_WIDTH = 352`, `SCREEN_HEIGHT = 320`, `LEVEL1_COLS = 9`, `LEVEL1_ROWS = 7` (2장 값 그대로; 쿨다운 상수의 단일 출처)
  - `createState(grid)` → `{ grid, bear:{col,row} }`; `B`를 찾아 시작 위치.
  - `tileAt(grid, col, row)` → 문자 또는 범위 밖이면 `null`.
  - `directionDelta(key)` → `{dc,dr}` 또는 `null` (ArrowUp/Down/Left/Right만).
  - `moveBear(state, key)` → 새 상태. 목적지가 `#` 또는 범위 밖이면 같은 위치. `L`·`.`·`B`는 통과 가능.
  - `canAcceptMove(lastMoveMs, nowMs)` → boolean. `nowMs - lastMoveMs >= MOVE_COOLDOWN_MS`; `lastMoveMs = -Infinity`이면 true.
- `src/main.js` (**R1 임시 구현; 8장은 R3 소관이며 대체 가능; 8장에 쓰지 않는다**): keydown에서 `event.repeat`이면 무시; `canAcceptMove(lastMoveMs, performance.now())` 통과 시 `moveBear`; 위치가 실제로 바뀐 경우에만 `lastMoveMs` 갱신; keydown 후 즉시 다시 그림. 맵 오프셋 (32,32). `MOVE_COOLDOWN_MS`는 logic.js에서 import. 렌더 루프·보간 없음.
- `test/logic.test.js`: `node --test test/`.

## 6. Open items (design-v1 검토 기본값; 사람이 문서 diff에서 확인, 별도 질문 없음)
- **O2 `L`·`B` 칸.** 격자는 글자 그대로. 기본값: `L`은 걸을 수 있고 바닥으로 그림, `B`는 곰이 떠나면 바닥으로 그림, 등불 그림·동작은 R2. 대안: `L` 비표시(승인 맵과 시각 불일치) / `L` 삭제(승인 맵 위반 → 금지). 편집: 4·5장.

- **O6 스프라이트 해상도.** 기본값 16×16 인덱스 배열 2배 확대. 대안: 32×32 직접(데이터 1024개×3). 편집: 4장.
- O8 기절 중 입력: R1에 기절 없음 → 닫힘 (R2).

4. →, ↓, ←, ↑ 를 각각 한 번씩 눌러 곰이 한 칸씩 즉시 이동하는지 보고, 한 방향키를 꾹 눌러도 한 칸만 이동하는지 본다. → 9장 4번
5. → 와 ↓ 를 같은 순간에 눌러 곰이 한 칸만 이동하는지 본다. 모두 떼고 다시 누르면 다시 한 칸 이동하는지 본다. → 9장 5번
6. 곰을 벽 옆까지 이동시킨 뒤 벽 쪽으로 키를 눌러 곰이 벽 안/화면 밖으로 가지 않고 제자리인지 본다. → 9장 6번
7. 곰·바닥·벽·맵 바깥 여백이 서로 뚜렷이 다른 색인지 본다. → 9장 7번

## 9. Risks & verification
- Node 버전: package.json 없이 ES module `.js`를 `node --test test/`로 돌리는 것은 Node의 모듈 자동 감지(Node ≥ 22.7 / 20.19)에 의존한다. 먼저 `node -v` 확인. import 실패 시 **멈추고** 6회 규칙에 따라 보고. 문서·사람 승인 없이 package.json 추가나 `.mjs` 개명 금지.
- file://에서 ES module 차단 → 사람 확인은 `python3 -m http.server 8000` 사용 (스크립트 준비 단계).
- 6장 hex는 에이전트 제안뿐 → 사람이 design-v1 검토 때 확인. 사람이 design-v1을 거부하거나 goal-1 후 색이 마음에 안 들면 `design-v2` / `replan-N`.
- R1 결정(벽·쿨다운·반복)이 R2·R3와 충돌 가능 → 문서에 "R1 결정, R2에서 재검토 가능" 표기.
- 스프라이트 오타로 곰이 안 보임 → 9장 3·7번 사람 확인으로만 확정.
- main.js 배선(상수 import, repeat 무시, 이동 시에만 갱신)은 자동 검증 불가 → goal-1 diff 검토 + 9장 4·5·6번 사람 확인.
- 자동 검증(보조, 완료 아님): `node --test test/`.
- **막힘 보고(6회 규칙):** 같은 시도를 6번 넘게 반복하지 않는다. 막히면 멈추고 (a) 시도한 것 (b) 실패 증거 (c) 막힌 지점의 기획서 장·수용 기준 번호를 보고. 이후는 ralplan에서 재계획.

## 10. Handoff
순서: executor design-v1(문서만) → critic 검토 → 사람 승인 → executor goal-1. **goal-1 executor는 구현 후 멈추고 보고한다("index.html을 열어 9장 수용 기준 1~7번을 보라"). 사람이 브라우저에서 9장 1~7번을 모두 확인한 뒤에만 완료.** 실패 시 fix-N 또는 6회 규칙에 따라 replan. 범위 확장 요구는 R2 ralplan으로.
