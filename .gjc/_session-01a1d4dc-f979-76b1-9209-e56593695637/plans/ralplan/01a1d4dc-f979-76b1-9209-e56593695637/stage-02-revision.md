### 3.2 구현 세부

**최고 점수 (7장, 2장 최고 점수 행)**
- `parseBest(raw)`: `^(0|[1-9][0-9]*)$`에 맞고 ≤ 3000인 문자열만 정수로, 나머지(null·빈 문자열·`abc`·`15.5`·`-5`·`3001`·`1e3`·앞 0)는 0.
- `nextBest(stored, score)` → `{ best: max(stored, score), save: score > stored }`. 저장값과 같으면 저장 안 함(7장 "더 클 때만").
- storage.js는 `store`(Storage 모양 객체)를 인자로 받는다. 모든 접근을 try/catch로 감싸 막히면 조용히 건너뛴다. main.js의 `window.localStorage` 접근 자체가 던질 수 있으므로(SecurityError) 그 접근도 try/catch로 감싸 null이면 "막힘".
- main.js: `prev.screen !== 'ending' && next.screen === 'ending'`인 순간 한 번 `loadBest`로 읽고(탭 두 개 대비) 메모리 최고값과 합쳐 `nextBest`, `save`면 `saveBest`. 엔딩 줄은 메모리 최고값을 그린다. 판 점수 = `game.level.score`(settleClear 후). 실패 화면은 읽지도 쓰지도 않는다(54번).
- 엔딩 `최고 점수 n` 줄(**D5**): goal-5에서는 기존 monospace 16 px, 기존 줄 y(110·140·190·230)는 그대로 두고 y=210에 추가(20 px 간격, 16 px 글자). 임시 배치는 goal-6에서 7장 y(80·110·160·190·240)와 글리프로 한 번에 바뀐다.

**효과음 (7장 효과음)**
- `soundEvent(prev, next)` → `'ending' | 'fail' | 'clear' | 'stun' | 'lamp' | null`. 순위 낮은 숫자 하나. 판정: next.screen이 ending으로 바뀜→ending; fail로 바뀜→fail; 둘 다 play이고 levelIndex가 늘어남→clear; 둘 다 play·같은 레벨이면 `next.stunUntilMs !== null && next.stunUntilMs !== prev.stunUntilMs`→stun, `lit.length` 증가→lamp; 그 밖은 null. 레벨이 바뀐 프레임은 levelIndex로 먼저 걸러 stun 비교가 새 레벨 상태를 보지 않게 한다.
- 호출 두 곳: `frame()`의 `tick` 전후, keydown의 `pressKey` 전후. `pressKey`가 내부에서 tick을 부르므로 한 입력에 사건은 한 번만 나온다.
- sound.js: 모듈 로드 시 AudioContext를 만들지 않는다(node에서 import 가능해야 함). `SOUND_TABLE`(사건 → 파형·[Hz, ms] 배열)을 export. `unlock()`은 첫 keydown에서 호출해 AudioContext를 만들고(throw 시 무음으로 계속) `state === 'suspended'`면 `resume()`. `play(name)`은 context 없으면 무시. 음 k의 시작 = 앞 음 길이 합, 게인은 5 ms 선형 상승 후 음 끝 40 ms 구간에서 0으로 하강(릴리즈를 음 길이 안에; 7장이 안/밖을 안 정함 → 구현 해석, OI-4). 마스터 게인 0.25.
- 탭 비활성 복귀 프레임의 일괄 처리(8장)는 `soundEvent`가 prev→next 한 쌍만 비교하므로 소리 하나만 난다. 기절이 한 프레임 안에서 시작·종료되면 무음일 수 있다(수용, §7).

**타이틀 (3장, 4장 타이틀 스프라이트)**
- sprites.js: `TITLE_NAME_SPRITES`(등·대·지·기·곰, 각 14행×14열, 값 null 또는 5)와 `SPRITE_TITLE_KEY`(12행×44열, **사용 인덱스가 정확히 {4,6,7}**, 글자 없음) 추가. 모양·세부(키캡 윤곽·하이라이트)는 구현자 재량이되 4장이 선언한 인덱스 집합 안에서만 그린다(OI-9, OI-11).

## 9. ADR

**Decision**: design-v4에서 새 후보 문서(4장 격자 삭제 + 이름·크기·사용 인덱스 선언, 1~48번 접미사 접기 + 범례 한 줄, 2장 난수 공식 삭제, 58번 favicon 예외)로 13,800자 한도를 맞추고(13,766자, 슬랙 34), goal-5(소리·최고 점수·타이틀)를 먼저, goal-6(글리프 47개·HUD·엔딩·실패)을 나중에 한 커밋씩 구현한다. 최고 점수는 엔딩만, 한글 글리프는 10×10(칸 11점·1점 2 px), 순수 `soundEvent`·`parseBest`·`nextBest`·글리프 배치는 logic.js, 재생·저장은 sound.js·storage.js. 스프라이트 격자의 기준은 sprites.js이고 4장의 사용 인덱스 선언을 테스트가 강제한다.

**Drivers**: 한도 13,800자(현재 14,081), 사용자 지시 준수(번호·[x]·팔레트·격자 문서 금지), 사람이 브라우저로 확인 가능한 완료 조건.

**Alternatives considered**: 1~48번 문장 압축(재확인 48개 필요, 기각), 격자 일부 유지(슬랙 34자라 불가), 최고 점수 엔딩+실패(요청 초과), 글리프 11×11·12×12(HUD 겹침 −5·−15 px), goal-5에 글리프 틀 포함(경계 붕괴), 글리프를 별도 새 파일로(8장 파일 목록 변경 필요), HTML favicon 링크(기획서 밖), 4장에 인덱스 선언 없이 격자만 삭제(스프라이트 기준이 코드뿐이라 검증 근거 없음, 기각).

**Why chosen**: A′는 문서만 고쳐 이미 확인된 1~48번 문장을 건드리지 않고 사용자가 확정했다. 10×10만 7장 HUD 규칙을 만족한다. goal 경계는 사용자 요청 분할과 일치해 사람 확인이 49~54, 55~58로 나뉜다. 순수 함수·가짜 store·문서 파싱 덕에 node 테스트로 canvas·AudioContext 없이 규칙을 검증한다. 4장 사용 인덱스 선언은 몇십 자로 격자 삭제의 검증 공백을 일부 메운다.

**Consequences**: 스프라이트 격자 모양은 문서 대조가 없다(사람 눈·diff 검토만). 슬랙이 34자(날짜가 다르면 최악 6자, 연도 포함 시 초과)라 문서 확장은 줄이기와 함께 해야 한다. goal-5는 임시 monospace 엔딩 줄을 만들고 goal-6에서 제거한다. 소리는 사람 귀로만 확인된다. README의 낡은 "보류" 절이 goal-5에서 고쳐진다. AGENTS.md의 "도트 웹폰트 예외" 문구는 R4 규칙과 어긋난 채 남는다(D9). 인덱스 테스트가 4장 문장 형식에 묶인다.

**Follow-ups**: 한글 오독 시 OI-6 기준으로 fix-N 또는 design-v5. 사람 확인 날짜 기록(범례 줄, §2.8). AGENTS.md 웹폰트 예외 정리는 별도 라운드. 효과음 수치·키 색 사용자 확인(OI-4, OI-11). 실제 `wc -m` 재측정(리더).
