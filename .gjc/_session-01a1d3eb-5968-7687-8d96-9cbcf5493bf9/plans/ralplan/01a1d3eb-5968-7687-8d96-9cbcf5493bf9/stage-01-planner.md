# R3 계획 (design-v3 → goal-4 → goal-5)

## 0. Summary · Intent Diff
- 목표: GAME_DESIGN v2→v3(문서만), goal-4(레벨 2·3), goal-5(소리·최고 점수·최종 화면·타이틀 도트). 이 계획은 계획 전용이며 코드·GAME_DESIGN.md·.gjc는 건드리지 않는다.
- 브리핑 사실 검증(직접 읽음): 맵 2·3 글자는 인터뷰 스펙 94~130행과 일치. 레벨 2 = 10×7, 곰 (1,1), 갈매기 (8,5)(거리 11 단독 최대), 등불 (3,2)(8,2)(2,4)(7,4), mapOffset (16,32). 레벨 3 = 11×9, 곰 (1,1), 갈매기 (9,7)(거리 14 단독 최대), 등불 (2,2)(8,2)(4,4)(6,4)(2,6), mapOffset (0,0). `tick`은 클리어 시 `createState(levels[N+1], nowMs, 점수+보너스)`로 다음 레벨을 시작하고 `pressKey`는 점등 뒤 `tick`을 한 번만 호출하므로 순서·합산·타이머 리셋·keydown 소비는 로직 변경 없이 성립한다. 한 판 최대 1200+1800=3000.
- **브리핑에 없던 발견(중요)**: `LEVELS`가 3개가 되면 `lastLamp()`로 레벨 1을 깨고 `LEVELS`를 넘기는 기존 테스트가 'ending'을 기대하다 깨진다(test 427, 433, 445, 517~526, 528~538행). 이 테스트들은 `[LEVEL1]`을 levels 인자로 넘기도록 고쳐 "마지막 레벨 클리어" 경로를 계속 검증한다(§5).
- 스프라이트 16×16 테스트는 기존 7종만 순회하므로 수정 불필요. 타이틀 스프라이트는 별도 테스트로 추가한다.
- 사용자 원문과 다르게 하는 것: 없음. 기획서에 없는 기능(신기록 연출·일시정지·음소거·레벨 번호 표시·곰 그림 추가)은 만들지 않는다. 6장 hex 8개 불변.

## 8. 8장 전문
- 구성: HTML + Canvas 2D + ES modules, 의존성·빌드 없음. 파일: index.html, src/{logic,levels,sprites,strings,sound,storage,main}.js.
- 루프: `requestAnimationFrame` 하나가 `performance.now()` 하나로 `tick`하고 그린다(프레임 속도와 무관). keydown: 방향키·스페이스에 `preventDefault()`(`event.repeat` 확인보다 먼저), `event.repeat` 무시, `pressKey`, 같은 시계. 쿨다운 기준 시각은 레벨 상태.
- 렌더링: 352×320 canvas, 도트마다 `fillRect`(보간 없음), 그리는 순서 4장. `canvas { image-rendering: pixelated }`를 index.html에 둔다(고해상도 화면에서 도트 번짐 방지, 로직 무관 한 줄).
- 글꼴: HUD·엔딩·실패는 브라우저 기본 monospace 16 px 유지, 웹폰트 미사용(이번 요청이 폰트를 금지하고 R2에서 읽힘이 확인됨).
- 오디오: `src/sound.js`가 OscillatorNode+GainNode로 7장 표를 합성. AudioContext는 첫 keydown(사용자 제스처)에서 만들고 `suspended`면 `resume()`. 사건 이름은 logic.js의 순수 `soundEvent(prevGame,nextGame)`가 이전·다음 상태를 비교해 돌려주고 main.js가 `tick`과 `pressKey` 호출 전후에 부른다. AudioContext가 없거나 생성이 실패하면 소리 없이 게임은 계속된다.
- 최고 점수: 키 `lighthouse-bear-best`(localStorage, 이 게임이 만드는 키는 이것 하나), 값은 0 이상 3000 이하 정수 십진 문자열(`BEST_SCORE_MAX=3000`은 logic.js 상수). 읽기 규칙 `parseBestScore`: 값이 없거나 정수 문자열이 아니거나(앞자리 0·부호·소수·지수 불가) 3000 초과면 0으로 본다. 갱신: 게임이 엔딩 또는 실패 화면으로 들어가는 순간 한 번, 점수가 현재 최고보다 클 때만 `nextBest` 후 저장. 실패 판 점수 포함. 최고 점수는 game 상태가 아니라 main.js의 변수라 새 판(`createGame`)에도 유지된다. localStorage 접근이나 쓰기가 예외를 던지면 조용히 건너뛰고 최고 점수는 이번 방문에서만 메모리로 유지한다.
- 외부 파일 없음: 오디오·이미지·폰트 요청 없음. 숫자 상수(60 000, 3 000, 300, 100, 20261113, 100점, 10점, 3000)는 logic.js 한 곳, 효과음 수치는 sound.js 한 곳.
- 탭 비활성 한계: 탭이 비활성이면 rAF가 멈추고 시계는 흐르므로 복귀한 첫 프레임에 밀린 갈매기 이동·기절·만료가 한꺼번에 처리돼 곧바로 기절·실패할 수 있다. R3도 일시정지를 만들지 않는다(10장). 이때 소리는 프레임 하나당 우선순위가 가장 높은 사건 하나만 난다.

## 10. 위험·사전 부검
1. 탭 복귀 일괄 처리: 한 프레임에 기절·실패가 몰린다 → 8장 한계 명시, 소리는 프레임당 하나, 일시정지는 10장 범위 밖.

## 12. ADR 초안
- **Decision**: design-v3(문서만) → goal-4(levels.js 2개 추가, 로직 무변경) → goal-5(상태 비교 `soundEvent`, logic 순수 `parseBestScore`/`nextBest`, 얇은 sound.js·storage.js, 도트 타이틀 스프라이트). 1~35번 문장은 불변이고 주석 표로 한정.
- **Drivers**: 문서-코드 일치, 기존 테스트·순수성 유지, 사람 확인 가능성.
- **Alternatives**: 문서 쪼개기(v3a/b), goal 연속 실행, 이벤트 배열 반환, main.js 안 저장, 한 장 타이틀 스프라이트 — §1 표.
- **Why chosen**: tick이 이미 레벨 전환·합산·리셋·소비를 처리하므로 goal-4는 데이터와 테스트만 바꾼다. 상태 비교는 logic 시그니처와 65개 테스트를 건드리지 않는다. storage 분리는 예외·비정상값을 node에서 테스트하게 한다.
- **Consequences**: LEVELS 3개로 기존 엔딩 테스트 5곳 교체 필요. goal-5가 파일 8개. 탭 비활성 한계가 남음. 소리는 사람이 귀로만 확인.
- **Follow-ups**: M1 답 반영, 소리·도트 모양은 diff 검토에서 조정, 일시정지가 필요해지면 새 라운드에서 기획.
