## 7. ADR 초안
- **Decision**: design-v3(압축 문서, 검사기 게이트) → goal-4(levels.js 2개, 로직 무변경, 테스트 교체·추가). goal-5는 보류.
- **Drivers**: 문서-코드 일치, 기존 테스트 보존, 채점 가시성.
- **Alternatives**: 문서 분할·다른 파일 분리, 9장만 압축, 게이트 없는 연속 실행.
- **Why chosen**: `tick`이 이미 전환·합산·리셋·엔딩을 처리하므로 goal-4는 데이터와 테스트만 바꾼다. 제자리 압축은 "GAME_DESIGN.md가 유일한 기준"을 지킨다.
- **Consequences**: 문서가 압축되어 출처 세부가 줄어듦. LEVELS 3개로 기존 엔딩 테스트 5곳 교체. 탭 비활성 한계 잔존.
- **Follow-ups**: 효과음·최고 점수·타이틀 도트는 이후 라운드에서 추가 가능. 이후 라운드는 문서 길이(앞 13,800자)를 다시 측정한다.

## 3. 화면 흐름

| 화면 | 들어오는 조건 | 보이는 것 | 받는 입력 | 나가는 조건 |
|---|---|---|---|---|
| 타이틀 | 페이지를 열 때, 엔딩·실패에서 스페이스바 | 배경색 전체, 가운데 "등대지기 곰"(인덱스 5)과 아래 "스페이스바로 시작"(인덱스 7), 맵·HUD 없음 | 스페이스바만 | 스페이스바 → 플레이(레벨 1, 처음 상태, 타이머 시작) |

소비 규칙(제안): 한 keydown은 하나의 효과만 낸다. 화면이 바뀐 keydown은 그 전환에 소비되어 새 화면에서 다시 처리하지 않는다. 타이틀→플레이, 엔딩·실패→타이틀, 레벨 N 클리어→N+1 전환도 한 입력에 한 번이며(타이틀에서 시작하려면 키를 뗐다 다시 눌러야 함), 마지막 레벨의 마지막 등불을 켜는 스페이스바는 엔딩까지만 간다. 입력 처리 전에 시간을 먼저 진행해 화면이 바뀌었으면(만료→실패) 그 입력은 버린다. `event.repeat`는 모든 화면에서 무시. 문구는 7장, 전환 연출 없음.

## 8. 기술 스펙

HTML + Canvas 2D + ES modules, 의존성·빌드 없음. 파일: index.html, src/{logic,levels,sprites,strings,main}.js, test/. `requestAnimationFrame` 루프 하나가 `performance.now()` 하나로 `tick`하고 352×320 canvas에 정수 배율 2로 `fillRect`(보간 없음), 순서는 4장. keydown은 `preventDefault()`(`event.repeat` 확인보다 먼저) → `event.repeat` 무시 → `pressKey`. 숫자 상수(100·300·3 000·60 000·20261113·100점·10점·32·352·320·칸 수)는 `src/logic.js` 한 곳, 다른 파일은 가져다 쓴다. 글꼴 monospace 16 px, 웹폰트 없음, 외부 이미지·오디오 파일 없음. 탭이 비활성이면 rAF가 멈추고 시계는 흘러 복귀 첫 프레임에 밀린 이동·기절·만료가 한꺼번에 처리되는 한계가 있고 일시정지는 만들지 않는다. 테스트 `node --test test/`, 실행 `python3 -m http.server 8000`.

확인 방법(1~48번 공통): `python3 -m http.server 8000` 후 http://localhost:8000 을 줌 100%로 본다(file://은 ES module 차단). 1번은 개발자도구로 canvas 크기, 2번은 칸 수를 센다. 1~7번은 스페이스바로 시작한 플레이 화면에서, 4~6번은 기절 중이 아닐 때 본다. goal-4는 36~48번만 확인해도 완료이고 1~35번 재확인은 회귀가 의심될 때 선택한다.
