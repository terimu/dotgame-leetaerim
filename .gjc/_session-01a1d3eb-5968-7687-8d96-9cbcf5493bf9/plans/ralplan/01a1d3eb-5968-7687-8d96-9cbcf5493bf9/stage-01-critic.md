# R3 계획 Critic 검토 (review pass 1, plan-only)

## 결론
Planner stage-01(sha256 58eb2b22…)은 사용자 요청 원문의 조건을 거의 모두 담았고, 기술 사실(tick의 레벨 전환·합산·리셋, 기존 테스트 5곳 파손, 맵 글자, 오프셋, 갈매기 시작 칸, 손계산 2040)은 실제 코드·기획서 v2와 대조해 맞다. 다만 (a) 사용자가 명시한 불변 조건(1~35번, 6장 hex, 10장 모두 완성)을 design-v3 게이트에서 확인하는 절차가 없고, (b) 타이틀 음절 스펙(14×14, 굵기 2점, 여백 1점)이 한글 판독 면에서 사실상 성립하지 않을 가능성이 높아 4장·7장·테스트 수치로 굳어지기 전에 고쳐야 하며, (c) stage-01 본문이 사용자 확정(M1=A)을 반영하지 않은 채 문서에 들어갈 문장(62번의 `M1 확정 전 가정`, 7장 M1 옵션 표)을 담고 있다. 진행을 완전히 막는 결함은 없으므로 REJECT가 아니라 ITERATE다. 아래 보강이 들어오면 실행 가능하다.

## Verdict

## 확인한 사실
- 요청 원문 조건 대조: 레벨 2·3 맵 글자(계획 §7 코드블록 :133-139, :142-150)는 인터뷰 스펙 :110-116, :121-129와 한 글자도 다르지 않다. 1→2→3·레벨 3 클리어=엔딩(36·40·42번), 점수 합산·타이머 리셋(38·41번), Web Audio 합성·외부 파일 금지(§7·§8·54번), localStorage 키 하나(59번), 최종 화면(64·65번), 타이틀 도트 글자·키 그림(61·62번), 5·7·8·10장 채움, 9장 36번부터 이어 붙임, 6장 hex 불변 선언, 각 문장 근거 장 인용, 세 레벨 점수 일치(43번+2040 테스트), "코드는 아직 고치지 않음"(계획 전용)은 모두 계획에 있다. 빠진 조건은 없고 확인 절차만 C-1처럼 부족하다.

- 코드 사실: logic.js `tick`은 클리어 시 `createState(levels[levelIndex+1], nowMs, settled.score)`로 다음 레벨을 만들고 마지막 레벨이면 ending으로 보낸다(logic.js:249-259). `pressKey`는 `g.levelIndex !== game.levelIndex`이면 입력을 버린다(:266). main.js `drawPlay`는 `mapOffset(grid[0].length, grid.length)`와 `lampTotal`을 쓰므로 레벨 2·3은 코드 변경 없이 그려진다. `LEVELS = [LEVEL1]`(levels.js:13)이고 기존 테스트가 이를 못박는다(test:423-425).
