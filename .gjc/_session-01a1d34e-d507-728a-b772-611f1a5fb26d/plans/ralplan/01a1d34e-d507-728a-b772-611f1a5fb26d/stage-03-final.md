| 등불 점등 | 새로 켜진 등불 1개당 +100점. 이미 켜진 등불·`L`이 아닌 칸 입력은 0점 | R2 사용자 확정 |
| 클리어 시간 보너스 | 맵 클리어 순간의 남은 시간(ms)을 초 단위로 내림한 값 × 10점. 남은 시간이 1초 미만이면 0점. 예: 남은 37.9초 → 370점, 남은 59.999초 → 590점, 남은 0.4초 → 0점, 경과 정확히 60 000 ms에 클리어 → 0점 | R2 사용자 확정 (예시는 계산 예) |
| 기절 | 점수 감점 없음 | R2 사용자 확정 |
| 실패 | 실패하면 1맵부터 재시작하고 점수는 0으로 초기화된다. 실패 화면은 그 판에서 얻은 점수를 보여 주고, 0으로 되돌리는 시점은 다음 새 판 시작(타이틀에서 스페이스바)이다 | R2 사용자 확정. 표시·시점: 에이전트 제안 |
| 맵 사이 합산 | 한 판의 점수는 맵을 넘어 이어서 합산한다(레벨 N 클리어 보너스까지 더한 점수로 레벨 N+1 시작). R3의 최종 합계는 이 표와 일치해야 하며 이 표가 단일 기준이다 | 이어 합산: 에이전트 제안 (사용자 확정 "R3 합계 일치"에서 도출) |
| 점수 표시 | HUD 가운데 `점수 n`. 엔딩·실패 화면에도 `점수 n` 한 줄을 보인다 | HUD: R2 사용자 확정. 엔딩·실패 화면 표시: 에이전트 제안 |
| 점수 저장·최고 점수 | R3. R2에서는 만들지 않는다 | R2 사용자 확정 |

레벨 1에서 가능한 점수: 최소 0, 최대 300 + 600 = 900 이하(보너스는 남은 시간이 60초일 때 600이 상한). 마지막 등불과 만료가 같은 시각이면 클리어 우선(위 "마지막 등불 vs 만료") + 보너스 0 → 300점. 점수 가산은 점등 시점(+100)과 클리어 전환 시점(보너스 한 번) 두 곳에서만 일어난다.

### 3.2 R2 임시 구현 표기 문단 초안
"R2 임시 구현: 페이지를 열면 `requestAnimationFrame` 루프가 매 프레임 `performance.now()`를 읽어 `tick`/`advance`로 상태를 진행하고 현재 화면을 그린다. 게임 상태는 시각을 인자로 받는 함수로만 바뀌므로 프레임 속도와 무관하다. keydown은 상태만 갱신하고(R1의 keydown 시 다시 그리기는 루프가 대체) 같은 `performance.now()` 시각을 쓴다. 쿨다운 기준 시각은 레벨 상태에 둔다. 브라우저 탭이 비활성이 되면 `requestAnimationFrame`이 멈추고 시계는 계속 흐르므로, 복귀한 첫 프레임에 밀린 갈매기 이동·기절·만료가 한꺼번에 처리되어 곧바로 기절하거나 실패할 수 있다. R2는 일시정지를 만들지 않는다. 틱 루프·입력·렌더링 방식은 8장(R3)이 정하며 R1·R2 임시 구현을 대체할 수 있다."

### 3.3 3장 화면 흐름 표 초안

| 화면 | 들어오는 조건 | 보이는 것 | 받는 입력 | 나가는 조건 |
|---|---|---|---|---|
| 타이틀 | 페이지를 열 때, 또는 엔딩·실패 화면에서 스페이스바 | `배경`색 전체, 가운데에 게임 이름 "등대지기 곰"(인덱스 5 글자)과 그 아래 "스페이스바로 시작"(인덱스 7). 맵·HUD 없음 | 스페이스바만. 방향키·엔터 등은 무시 | 스페이스바 → 플레이(1맵, 처음 상태, 이 순간 타이머 시작) |

화면 전환 keydown 소비 규칙(에이전트 제안): 한 번의 keydown은 정확히 하나의 효과만 낸다. 화면이 바뀐 keydown은 그 전환에 소비되어 새 화면에서 다시 처리하지 않는다. 스페이스바 한 번이 타이틀→플레이를 일으키면 같은 입력이 플레이에서 점등을 일으키지 않고, 엔딩·실패→타이틀을 일으키면 같은 입력이 타이틀→플레이를 일으키지 않는다(타이틀에서 시작하려면 키를 떼었다가 다시 눌러야 한다). 마지막 등불을 켜는 스페이스바는 점등+클리어를 일으키고 같은 입력이 엔딩에서 타이틀 전환을 일으키지 않는다. `event.repeat`는 모든 화면에서 무시한다. 입력 처리에서는 먼저 시간을 진행해 화면이 바뀌었으면(예: 만료로 실패) 그 입력은 새 화면에서 처리하지 않고 버린다.

R2 임시 문구(7장 R3가 대체 가능), 모두 `src/strings.js` 한 곳(타이틀·HUD 라벨·실패·엔딩·안내 전부):
- 타이틀: "등대지기 곰" / "스페이스바로 시작" (R2 사용자 확정)
- 엔딩(스펙 F10 원문): 「등대에 다시 불이 들어왔다. 곰은 아침까지 등불을 지킨다.」 `strings.js`에는 공백 위치가 고정된 두 문자열("등대에 다시 불이 들어왔다." / "곰은 아침까지 등불을 지킨다.")로 두고 `textAlign = center`로 두 줄에 그린다(글자 변경 금지; 두 문자열을 공백 하나로 이으면 원문과 같다). R2 임시: 레벨 1만 깬 결과에 뜨며 "3개 맵"과 의미가 어긋난다
- 실패(에이전트 제안, 최소화): 「밤이 끝났다.」
- 안내(에이전트 제안): 「스페이스바로 처음 화면」
- 점수 줄(에이전트 제안): 「점수 n」
- HUD 라벨(에이전트 제안): 「등불」, 「점수」, 「남은 시간」
문구 색은 인덱스 7(타이틀 이름만 인덱스 5), 가운데 정렬. 전환 연출(페이드 등)은 없다: 상태가 바뀌면 다음 프레임에 바로 다른 화면이 보인다(에이전트 제안).

### 3.6 9장 구조 변경
- 소제목 `### R1 임시 수용 기준` → `### 수용 기준 (1~7번 R1, 8번~ R2)`. 설명 문단의 "R1(goal 하나...)만의 임시 기준이다. R2가 이어서 확장한다."를 "1~7번은 R1 goal-1의 기준이고 R2에서도 그대로 유효하다. 8~23번은 goal-2, 24~35번은 goal-3의 기준이다."로 교체. 나머지 문장(보고 형식·테스트 통과는 완료 아님·fixture 스크린샷 금지)은 유지.
- 1~7번 줄은 번호·문장·`[x] 사람 브라우저 확인 2026-11-13`까지 한 글자도 바꾸지 않는다. 8번부터 이어 붙인다(`[ ]` 표기).
- "확인 범위"에 R2 항목 추가(4절 하단). "확인 방법"은 R2 항목도 같은 서버 방법. 한 줄 추가: goal-3 이후에는 페이지를 열면 타이틀이 먼저 보이므로 **1~7번은 스페이스바로 시작한 플레이 화면에서 본다**(문장은 그대로 유효). R2 이후 R1 4·5·6번을 다시 볼 때는 갈매기·기절이 끼어들 수 있으므로 기절 중이 아닐 때 확인한다(사람이 8~35번만 확인해도 goal 완료이고 1~7번 재확인은 회귀 의심 시 선택).
- R1 3번 "안쪽은 바닥" ↔ `L` 칸 등불: 등불은 바닥 타일 위에 얹는 투명 스프라이트이므로 `L` 칸도 바닥 위에 서 있는 것으로 3번 문장과 모순되지 않는다. 3번 확인 시 그림은 "바닥 위의 꺼진 등불 3개"로 보인다(문장 수정 안 함, D20).

## 4. 9장 신규 수용 기준 초안 전문 (8~35번)

형식은 R1과 같다: `N. 한 문장. (근거 장) [ ] 사람 브라우저 확인`. 1~7번은 3.6절대로 그대로.

**goal-2 (8~23번)** — goal-2 시점에는 타이틀이 없고 페이지를 열면 바로 플레이 화면이다(R2 임시, goal-3이 앞에 타이틀을 넣는다). 등불을 다 켜거나 시간이 0이 되면 화면은 멈춘 플레이 화면에 머문다(화면 전환은 goal-3).
8. 맵 안쪽 세 칸(5장 격자의 `L` 위치)에 꺼진 등불 그림이 바닥 위에 보이고, 등불 칸의 바닥은 다른 바닥 칸과 같은 색이다. (4장 등불, 5장 레벨 1 격자 `L`)
9. 곰이 꺼진 등불 칸에 서서 스페이스바를 한 번 누르면 그 칸의 등불이 켜진 그림으로 바뀐다. (2장 "점등" 행, 4장 등불)
10. 곰이 등불이 없는 바닥 칸에서 스페이스바를 눌러도 어떤 등불도 켜지지 않는다. (2장 "점등" 행)
11. 이미 켜진 등불 칸에서 스페이스바를 다시 눌러도 그 등불이 꺼진 채로 돌아가지 않고 HUD의 켠 등불 수와 점수도 늘지 않는다. (2장 "점등" 행, "HUD" 행, 점수 표 "등불 점등" 행)
12. 화면 아래 띠 왼쪽에 `등불 0/3`으로 시작하는 글자가 보이고 등불을 켤 때마다 앞 숫자가 1씩 오른다. 3/3이 되면 곰과 갈매기가 더 움직이지 않는다. (2장 "HUD"·"맵 순서·승리·실패" 행, 6장 `배경` 띠)
13. 화면 아래 띠 가운데에 `점수 0`으로 시작하는 글자가 보이고 새 등불을 켤 때마다 100, 200, 300으로 오르며, 이미 켠 등불이나 등불 없는 칸에서 스페이스바를 눌러도 오르지 않는다. (2장 점수 표 "등불 점등"·"점수 표시" 행, "HUD" 행)
14. 화면 아래 띠 오른쪽에 `남은 시간 60`으로 시작하는 글자가 보이고 약 1초마다 1씩 줄어 약 60초 뒤 0에서 멈추며, 0이 되면 곰이 더 움직이지 않는다. (2장 "제한시간"·"HUD" 행)
15. 시작 직후 갈매기가 맵의 오른쪽 아래 구석 안쪽 칸에 있다가(첫 이동은 약 0.3초 뒤) 곰을 향해 한 칸씩 다가오고, 벽 칸이나 맵 밖으로 나가지 않는다. (2장 "갈매기 배치"·"갈매기 이동" 행, 4장 갈매기)

### 확인 범위 (신규 항목 중 화면으로 판정할 수 없어 테스트·diff 검토로 덮는 것)
- 정확한 60 000 ms·3 000 ms·300 ms 경계, 마지막 등불과 만료가 같은 시각일 때 클리어 우선(2장 "마지막 등불 vs 만료"), 보너스 계산의 정확한 값(남은 37.9초 → 370점, 59.999초 → 590점, 0.4초 → 0점 등): 사람이 재지 않는다. 경계·계산 단위 테스트로 덮는다. 29번은 HUD 시간 표기(올림)와 보너스(내림)가 달라 ±1초 근사로만 사람이 본다.
- 시드 20261113·mulberry32·후보 선택식·사건 시각 규칙: 같은 시드 → 같은 난수열, 같은 입력 스크립트를 두 번 재생하면 같은 상태, 프레임을 나눠 진행해도 같은 결과는 테스트로 덮고, 시드를 쓰는 코드가 상수 한 곳뿐인지는 goal-2 diff 검토로 덮는다. 사람이 두 번 시작해 갈매기 경로를 눈으로 비교하는 것은 300 ms 간격에서도 신뢰할 수 없어 수용 기준에 넣지 않았다.
- 인접 칸 비기절(스펙 F9): 18번으로 사람이 볼 수 있다. 300 ms 간격이라 갈매기가 인접해 있는 시간이 최대 약 0.3초로 짧아 한 번에 안 보일 수 있으므로 "여러 번 시도" 문구와 "거리 1이면 기절 아님" 단위 테스트로 보완한다(100 ms였다면 사실상 확인 불가였던 항목이 300 ms에서 확률적으로 확인 가능해졌다).
- 곰이 갈매기 칸으로 걸어 들어가는 경우와 갈매기가 곰 칸으로 들어오는 경우 둘 다 기절: 17번은 어느 쪽이든 발생만 본다. 두 경로 각각은 단위 테스트로 덮는다.
- 곰이 갈매기를 피할 수 있는지(16번): 곰의 연타 속도(초당 최대 10칸)가 갈매기(초당 약 3.3칸)보다 빨라 사람이 눈으로 확인할 수 있다. 정확한 비율은 상수 테스트로 덮는다.
- 스페이스바가 이동 쿨다운에 영향이 없음, `preventDefault`(`event.repeat` 확인보다 먼저, `event.key === ' '`), `event.repeat` 무시, rAF 루프가 `performance.now()` 하나만 쓰는지, 숫자(300·3 000·60 000·100·20261113·점수 100·10)가 `src/logic.js` 상수 한 곳에만 있고 다른 파일이 가져다 쓰는지: diff 검토(main.js). 스페이스 직후 방향키가 바로 먹는지는 100 ms라 사람이 판정하기 어렵다.
- 타이틀에서 스페이스바 한 번이 시작과 점등을 동시에 일으키지 않는 규칙(소비 규칙): 레벨 1의 시작 칸은 `B` 칸이라 등불이 없어 사람이 점등 이중 발생을 눈으로 볼 수 없다. 화면 전환 단위 테스트(상태 불변·한 입력 한 효과)로 덮고 사람은 34번(스페이스 한 번 = 타이틀까지만)·26번(시작 시 타이머)으로 간접 확인한다.
- 팔레트 소속(코드의 hex가 6장 hex와 같은지)과 "6장 8색 밖의 색이 없는지": R1처럼 테스트로 주장하지 않는다. 사람이 design-v2·goal-2·goal-3 diff에서 hex 텍스트를 눈으로 비교한다. 스프라이트 값 범위(null 또는 0..7)는 테스트.
- 탭 비활성 후 복귀 시 밀린 갈매기 이동·기절·만료가 한꺼번에 처리되는 한계(3.2절): R2는 일시정지를 만들지 않으므로 수용 기준에 넣지 않고 R3(8장) 후속으로 둔다.
- 13번 "약 60초"·14번의 시간 흐름: 사람이 초시계로 거칠게 본다(±1초 이내면 통과).

## 6. goal-2 / goal-3 정의

### 상태 형태 (goal-2가 정하고 goal-3이 그대로 전제)

레벨 상태(goal-2):
```
{ grid, bear: {col,row}, gull: {col,row},
  lit: [ {col,row}, ... ],
  score: number,                    // 한 판 누적 점수(점등분, goal-3에서 보너스 가산)
  status: 'playing' | 'cleared' | 'failed',
  startMs, endMs: number | null,    // cleared/failed 순간 기록, 남은 시간 고정에 사용
  lastMoveMs: number,               // 곰이 마지막으로 실제 이동한 시각, 시작 시 -Infinity
  nextGullMoveMs,                   // 직전 예약 시각 + 300 (기절 후 stunUntilMs + 300)
  stunUntilMs: number | null,       // null = 기절 아님. 사건 시각 + 3000
  rng: uint32 }                     // mulberry32 상태
```
게임 상태(goal-3 신설, 레벨 상태를 감쌈): `{ screen: 'title' | 'play' | 'ending' | 'fail', levelIndex, level }` (`level`은 title에서 null).
상수(전부 `src/logic.js` 한 곳, 값은 기획서 2장): `LEVEL_TIME_MS = 60000`, `STUN_MS = 3000`, `SEAGULL_MOVE_INTERVAL_MS = 300`, `RNG_SEED = 20261113`, `LAMP_SCORE = 100`, `CLEAR_BONUS_PER_SECOND = 10`, 기존 `MOVE_COOLDOWN_MS` 등. R1 `moveBear`는 `{...state, bear}`로 다른 필드를 보존하도록 바꾼다(R1 테스트는 `.bear`만 보므로 유지).

### goal-2: "등불·갈매기·60초 타이머·기절이 동작한다"

- **목표 한 문장**: 곰이 `L` 칸에서 스페이스바로 등불을 켜 점수(+100)가 오르고, 300 ms마다 다가오는 갈매기와 같은 칸이 되면 약 3초 기절하며, 60초 타이머가 HUD에 보인다(페이지를 열면 바로 플레이, 클리어·시간 초과는 멈춘 화면).
- **사람이 볼 완료 조건**: 9장 8~23번. 근거: 2장 "점등"·"스페이스바 입력"·"이동 쿨다운 위치"·"제한시간"·"마지막 등불 vs 만료"·"시간 진행 규칙"·"기절"·"기절 중"·"기절 시 갈매기"·"갈매기 배치/이동/이동 간격"·"난수"·"충돌 판정 시점"·"HUD" 행과 점수 표 "등불 점등"·"기절"·"점수 표시" 행, 4장 갈매기·등불·곰 기절 스프라이트, 5장 레벨 1 격자 `L`, 6장 사용처(인덱스 0~7).
- **건드릴 파일 (5개)**: `src/logic.js`, `src/main.js`, `src/sprites.js`, `src/strings.js`(신규, HUD 라벨만), `test/logic.test.js`(`test/index.js`가 이 파일 하나만 import하므로 테스트 파일을 늘리지 않는다). `src/levels.js`는 건드리지 않는다.
- **순수 함수 시그니처 초안**:
  - `createState(grid, nowMs, startScore = 0, seed = RNG_SEED) → state` — `nowMs`는 필수(숫자가 아니면 throw; 인자 누락 시 `nextGullMoveMs`가 NaN이 되어 조용히 통과하는 것을 막는다). 곰 `B` 칸, 갈매기 `placeGull`, `lit: []`, `score: startScore`, `status: 'playing'`, `startMs = nowMs`, `endMs: null`, `lastMoveMs: -Infinity`, `nextGullMoveMs = nowMs + SEAGULL_MOVE_INTERVAL_MS`, `stunUntilMs: null`, `rng: seed`.
  - `lampCells(grid)`, `farthestFloorCell(grid, from)`, `nextRandom(rng) → { value, rng }`
  - `gullCandidates(grid, gull, bear) → [{col,row}]`(순서 위·아래·왼쪽·오른쪽), `stepGull(state) → state`(`floor(value × 후보 수)`번째, 후보 0개여도 난수 한 번 소비)
  - `advance(state, nowMs) → state`: 사건을 사건 시각 순서로 처리하되 상한은 min(nowMs, startMs + LEVEL_TIME_MS). 사건: 기절 종료(시각 `stunUntilMs`, 같은 시각이면 갈매기 이동보다 먼저), 갈매기 이동(시각 `nextGullMoveMs`, 처리 후 `nextGullMoveMs += 300`), 갈매기 이동으로 같은 칸이 되면 그 이동의 예약 시각 t에 기절 시작(`stunUntilMs = t + STUN_MS`, 갈매기를 `farthestFloorCell`로 재배치, `nextGullMoveMs = stunUntilMs + 300`, 기절 중에는 갈매기 이동 사건 없음). 처리 후 nowMs > startMs + LEVEL_TIME_MS이면 `status: 'failed'`, `endMs = startMs + LEVEL_TIME_MS`. `playing`이 아니면 그대로.
  - `pressMove(state, key, nowMs) → state`: `advance` 후 `playing`이고 기절 아니고 `canAcceptMove(state.lastMoveMs, nowMs)`이면 `moveBear` 적용. 곰이 실제로 이동했을 때만 `lastMoveMs = nowMs`, 이동 직후 갈매기와 같은 칸이면 기절 시작(`stunUntilMs = nowMs + STUN_MS`, 갈매기 재배치, `nextGullMoveMs = stunUntilMs + 300`). 벽 막힘·쿨다운 거부는 상태 불변(`lastMoveMs` 포함).
  - `pressLight(state, nowMs) → state`: `advance` 후 `playing`이고 기절 아니고 곰이 아직 켜지지 않은 `L` 위이면 점등 + `score += LAMP_SCORE`, 전부 켜지면 `status: 'cleared'`, `endMs = nowMs`. `lastMoveMs`는 건드리지 않는다.
  - `remainingMs(state, nowMs)`, `remainingSeconds(state, nowMs) → 올림 0..60`, `litCount(state)`, `lampTotal(state)`
  - main.js 배선: keydown에서 `event.key`가 `' '` 또는 방향키이면 `preventDefault()`를 먼저 호출하고 그다음 `event.repeat`이면 return, 방향키는 `pressMove`, 스페이스는 `pressLight`(쿨다운 변수는 main에 없음). rAF 루프는 `performance.now()`를 읽어 `advance`하고 그린다.

## 8. 위험·검증·6회 규칙·R1 충돌 지점

### 위험과 완화
- **R-1 (해소) 승리 확인 난이도**: 이전 초안은 갈매기 100 ms가 곰의 최고 속도와 같아 따돌릴 수 없다고 봤다. 사용자 확정 300 ms로 곰이 연타하면 갈매기보다 빠르다(곰 초당 최대 10칸, 갈매기 초당 약 3.3칸). 사람이 눈으로 확인 가능(9장 16번). 잔여 위험: 300 ms에서도 갈매기가 인접해 있는 시간이 짧아 18번을 한 번에 못 볼 수 있음 → "여러 번 시도" 문구와 단위 테스트로 보완.
- **R-2 (해소) 점수 표 오해석**: 사용자가 해석 A로 확정. 잔여 위험: 점수 숫자가 2장·HUD·테스트·goal에 분산 → 2장 점수 표가 단일 기준이고 숫자는 `src/logic.js` 상수 한 곳(`LAMP_SCORE`, `CLEAR_BONUS_PER_SECOND`), 테스트 기대값은 문서 예(370, 590, 0, 670 등)에서 손으로.
- **R-3 (중간) 백그라운드 탭**: rAF 정지 중 `performance.now()`는 흐르므로 복귀 시 즉시 실패하거나 갈매기 catch-up 이동이 몰린다. 완화: R2는 일시정지를 만들지 않는다(기획서에 없음). 3.2절 "R2 임시 구현 표기"와 9장 확인 범위에 한계를 기록하고 R3(8장) 후속으로 둔다.
- **R-4 (중간) 로직 크기**: goal-2가 logic.js·테스트를 크게 늘린다. 완화: 함수 단위로 나누고 시각 사건 처리(`advance`)를 단일 함수에 모음. 막히면 6회 규칙.
- **R-5 (낮음) 새 스프라이트 모양**: 초안은 사람이 v2 diff에서 모양을 고친다. 16×16·인덱스 0~7 검사는 테스트.
- **R-6 (낮음) 글꼴**: monospace 한글 폭 차이로 가운데 정렬이 어긋날 수 있음. R2 임시이며 7장·R3에서 도트 폰트 결정.
- **R-7 (중간) 보너스 근사 확인**: HUD 올림 표기와 보너스 내림이 달라 사람이 29번을 정확히 확인할 수 없다(±1초 근사). 완화: 정확한 값은 단위 테스트, D29 대안(HUD 내림)을 사람이 v2 diff에서 선택할 수 있음(사람 승인 항목).
- **R-8 (낮음) 엔딩 문구 의미 어긋남**: 레벨 1만 깬 결과에 "3개 맵" 엔딩 문구가 뜬다. 완화: 사용자 확정, 문서에 "R2 임시" 표기, R3에서 레벨 3 클리어로 해소.
- **R-9 (낮음) goal-3 크기**: 5개 파일 상한에 정확히 걸린다. 완화: 6절 분할 검토 문단(엔딩 문구 두 문자열 + textAlign center로 main.js 팽창 완화, 6번째 파일이 필요하면 멈추고 보고).
- **R-10 (낮음) logic.js 단일 파일 집중**: 5개 파일 상한이 monolith를 강제한다. 완화: R3 전 `gull`/`screens` 분리를 후속으로 권장.

### R1 결정과의 충돌 지점 (R1 결정 자체는 불변)
1. keydown 때 다시 그리던 R1 임시 구현 → rAF 루프로 교체("R2 임시 구현" 표기, 8장 대체 가능). 벽 막힘·쿨다운·repeat 규칙은 불변.
2. `moveBear`가 `{grid, bear}`만 돌려줌 → `{...state, bear}`로 필드 보존(R1 테스트는 `.bear`만 확인).
3. `createState(grid)` → `createState(grid, nowMs, startScore, seed)`로 확장하고 `nowMs`는 필수. R1 테스트 호출을 `createState(LEVEL1, 0)`으로 갱신(`.bear` 기대값 불변).
4. `L` 칸 그리기 ↔ R1 9장 3번 "안쪽은 바닥": 바닥 위에 투명 등불을 얹어 해소(3번 문장 불변, D20).
5. 스페이스바 ↔ 쿨다운: 스페이스는 이동 쿨다운을 시작하지 않고 막히지도 않는다. 쿨다운 기준 시각 `lastMoveMs`는 main.js 지역 변수에서 레벨 상태 필드로 이동하고 `pressMove`가 `canAcceptMove`를 적용한다(규칙은 불변, 보관 위치만 이동, D32). R1 테스트 "방향키 외의 키는 이동하지 않는다"(스페이스 포함)는 그대로 유효(점등은 별도 함수).
6. 틱 루프(rAF) ↔ R1 "시간 기준은 `performance.now()` 하나": 콜백 안에서 `performance.now()`를 호출해 유지.
7. 2장 "벽 막힘" 행의 "R2에서 채운다" 문구, 5장 "R1 범례 규칙" 문장, 6장 "예약" 문구, 9장 소제목·설명 문단은 문서만 수정(결정 불변).
8. R1 스프라이트 테스트(3종 순회)에 새 4종 추가. `test/index.js`가 `logic.test.js`만 import하므로 새 테스트 파일을 만들지 않는다.
9. 페이지를 열면 goal-2 시점에는 바로 플레이, goal-3부터 타이틀 → goal-2의 "페이지 열림 = 타이머 시작"이 goal-3에서 "스페이스바로 시작 = 타이머 시작"으로 바뀌는 점은 `createState` 호출 지점만 바뀌므로 로직 영향 없음(3장에 명시). R1 1~7번은 goal-3부터 스페이스바로 시작한 플레이 화면에서 본다(9장 확인 방법).

## 10. ADR 초안

- **Decision**: design-v2 한 번으로 2장 나머지 규칙·점수 표, 3장(타이틀·플레이·엔딩·실패), 4장 신규 오브젝트, 6장 사용처, 9장 8~35번을 채우고 사람 승인 뒤 goal-2(8~23번: 등불·갈매기·타이머·기절·점등 점수)와 goal-3(24~35번: 타이틀·승패·화면 전환·클리어 보너스·초기화)을 순서대로 구현한다. 갈매기는 300 ms 간격으로 표준 mulberry32(시드 20261113, 레벨 시작마다 초기화, 값 = uint32/2^32, 후보 `floor(값×후보 수)`번째)와 사건 시각 기준 시각 인자 순수 함수(`advance`)로 접근하고, 쿨다운 기준 시각은 레벨 상태 필드이며, 틱은 R2 임시 rAF 루프로 한다. 점수는 2장 점수 표(100점/등불, 남은 시간 초(내림)×10)가 단일 기준이다.
- **Drivers**: 사람이 눈으로 판정 가능한 기준(네 화면 모두 실제 플레이로 도달), 사용자 확정값 준수·기획서 외 기능 금지(점수 저장·레벨 2·3 제외), goal ≤ 5파일·6회 규칙·결정적 테스트.
- **Alternatives considered**: 문서 2회 분할(옵션 B), 단일 goal(옵션 C), 점수를 한 goal에 몰기, setInterval 고정 틱, 기절 후 갈매기 무적 시간·밀어내기, 갈매기 간격 100/200 ms, 점수 B(수치 표)·C(표시 점수), 실패 시 즉시 자동 재시작, 엔터 재시작, 중간 "클리어" 화면, HUD 시간 내림 표기, 타이틀 없음, 쿨다운 기준 시각을 main.js 지역 변수로 유지.
- **Why chosen**: 사용자 요청과 R1 절차(design-vN → critic → 사람 승인 → goal-N → 사람 확인)에 일치하고 승인 게이트가 한 번이다. 사건 시각 기준 `advance`는 프레임·탭 상태와 무관해 8장이 루프를 바꿔도 로직이 안 바뀌고 프레임 분할 불변식으로 테스트할 수 있다. 쿨다운을 레벨 상태에 두면 goal-3의 `pressKey`가 레벨 형태를 main에 노출하지 않고 쿨다운도 테스트 안에 들어온다. 기절 시 갈매기 이동은 새 숫자 없이 무한 재기절을 막는다. 점등 점수를 goal-2, 보너스·초기화를 goal-3에 둔 것은 사람이 각각 볼 수 있는 시점과 일치한다. 스페이스 한 번 = 한 효과 규칙과 점수 가산 한 지점으로 이중 발생을 막는다.
- **Consequences**: v2 diff가 커서 critic·사람 검토 부담. 갈매기 300 ms로 승리 확인은 가능하지만 인접 비기절(18번)은 확률적이다. goal-2 로직에 `status`·`endMs`·`score`·`lastMoveMs`가 들어가 goal-3 화면 전환의 전제가 된다. goal-3은 5개 파일 상한에 정확히 걸려 6번째 파일이 필요하면 replan. HUD 올림/보너스 내림 불일치로 29번은 근사 확인(사람 승인 항목). 엔딩 문구가 R2에서 "3개 맵"과 의미가 어긋난 채 임시 표시된다. 탭 비활성 복귀 시 catch-up 한계가 있다. R2 임시 문구·글꼴·rAF는 R3(7장·8장)가 대체.
- **Follow-ups**: R3에서 레벨 2·3 격자와 `LEVELS` 확장(엔딩은 레벨 3 클리어), 레벨별 시드 초기화·점수 이월 확인, 점수 저장·최고 점수(2장 표와 합계 일치), 7장 문구·도트 폰트, 8장 루프·입력 정식화, 백그라운드 탭 처리 여부, R3 전 `gull`/`screens` 분리 검토, `fix-N` 시 문서 선수정, 사람 책임 스크린샷 4장 제출.

## 11. 핸드오프
- design-v2 작성·goal-2·goal-3 구현: `executor` (goal 하나에 커밋 하나, 메시지 접두사 `design-v2:`/`goal-2:`/`goal-3:`). goal-3은 goal-2 사람 확인 뒤에만. design-v2 작성자는 난수 행의 첫 3개 값을 src와 독립된 node 한 줄로 산출해 문서에 적는다.
- design-v2 검토: `critic` (8절 점검 포인트), 시간·상태 모델·점수 단일 전환 지점·사건 시각 규칙이 의심되면 `architect`.
- 사용자 결정은 모두 확정됐으므로 승인 요청 시 에이전트 제안 목록(9절, 특히 HUD 올림 vs 보너스 내림)만 제시. 사람 책임 산출물(스크린샷 4장)은 goal-3 사람 확인 때 사람이 직접 찍는다.
