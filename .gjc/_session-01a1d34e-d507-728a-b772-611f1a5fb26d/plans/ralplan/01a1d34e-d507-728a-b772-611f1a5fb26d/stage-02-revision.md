# R2 계획 개정본 (planner revision, stage_n 2): GAME_DESIGN v1 → v2 문서 확장 + goal-2 + goal-3

상태: 개정본. intent reconciliation(stage-01-intent.md)의 사용자 확정 4건을 반영한 완결본. critic 검토와 사람 승인 전. 코드·GAME_DESIGN.md·`.gjc/`는 이 계획에서 수정하지 않았다(읽기 전용 역할).
순서: design-v2(GAME_DESIGN.md만, 커밋 `design-v2:`, 코드 금지) → critic → 사람 승인 → goal-2(`goal-2:`) → 사람이 브라우저에서 9장 8~23번 확인 → goal-3(`goal-3:`) → 사람이 9장 24~35번 확인. goal-3은 goal-2 사람 확인 뒤에만 시작한다. goal 하나에 커밋 하나, 같은 시도 6회 초과 반복 금지.

## 0. 요약

- R2 = 목표물(등불 점등)·위협(갈매기·기절)·타이머·점수 점등분(goal-2) + 승패·화면 전환·타이틀·점수 보너스/초기화(goal-3). 레벨 2·3 격자, 사운드, 점수 저장·최고 점수·리더보드, 10장 범위 밖 전부는 R3 이후이므로 넣지 않는다.
- design-v2는 2장 나머지 규칙과 **점수 표**, 3장 화면 흐름(타이틀·플레이·엔딩·실패), 4장 갈매기·등불 오브젝트와 16×16 스프라이트, 6장 사용처 열, 9장 8번~35번(신규 28개, 총 35개)을 채운다. 6장 8색 hex·개수 불변.
- **R2 사용자 확정 4건 반영**: (1) 점수 표 = 해석 A(등불 1개 100점, 클리어 시 남은 시간 초(내림)당 10점, 기절 감점 없음, 실패 시 0 초기화, HUD 표시, 저장은 R3). (2) 맵 순서 규칙 = 일반형, R2 마지막 레벨 = 레벨 1이므로 레벨 1 클리어 = 엔딩(임시, 문구는 스펙 원문). (3) 타이틀 화면 추가, 재시작 입력은 스페이스바(엔터 제안 폐기), 스페이스 한 번 = 전환 또는 점등 중 하나만. (4) 갈매기 이동 간격 300 ms.
- **design-v2 승인 차단 항목: 없음.** MOI-1·2·3은 사용자 확정으로 해소. 남은 것은 모두 "에이전트 제안(사람이 v2 diff에서 확인)"이며 차단이 아니다(9절).

## 1. RALPLAN-DR 요약

### Principles
1. 기획서(GAME_DESIGN.md)가 유일한 기준이다. 애매하면 문서를 먼저 고치고 사람이 본 뒤에 코드를 쓴다 (AGENTS.md). 점수 표 같은 사용자 확정 값은 2장 표 한 곳이 단일 기준이며 R3 합계도 이 표와 일치해야 한다.
2. goal 완료 = 사람이 브라우저에서 9장 번호를 확인. 테스트 통과·fixture 스크린샷은 증거가 아니다.
3. R1 확정 결정(벽 막힘=제자리, 이동 후 100 ms 쿨다운, keydown 1회=1칸, event.repeat 무시)은 불변. v2 diff에서 새로 정한 것은 출처(스펙 Rn / R2 사용자 확정 / 에이전트 제안)를 표시한다.
4. 시간·난수·점수는 인자(`nowMs`, 시드 상태, 남은 ms)로 받는 순수 함수로 만들어 결정적으로 테스트한다. 화면에서 관찰 불가능한 것은 수용 기준이 아니라 "확인 범위"에 두고 테스트·diff 검토로 덮는다.
5. 기획서·인터뷰 스펙·사용자 확정에 없는 것은 만들지 않는다. 모르는 값은 만들지 않고 에이전트 제안으로 표시한다.

### Decision Drivers (상위 3)
1. 사람이 브라우저에서 예/아니오로 판정 가능한 기준 (goal 크기·관찰 가능성, 네 화면 모두 실제 플레이로 도달 가능).
2. 사용자 확정값 준수(점수 표·300 ms·스페이스 재시작) + 기획서에 없는 기능 금지(점수 저장·레벨 2·3 등).
3. goal 하나 ≤ 5개 파일·6회 규칙 안에서 끝낼 수 있는 분할, 결정적(시드·시간 인자) 테스트 가능성.

### Viable Options (계획 수준)

**옵션 A (선택): 문서 한 번(design-v2 전체) → goal-2 → goal-3.**
- 장점: 사용자 요청 그대로(v2에 2장·3장·9장 한 번에). 승인 게이트 1회. goal-3이 의존할 상태 형태·점수 필드를 문서·goal-2에서 먼저 굳힘.
- 단점: v2 diff가 커서 critic·사람 검토 부담이 큼(타이틀·점수 추가로 더 커짐). 3장(타이틀·승패 화면)은 goal-3까지 코드로 검증되지 않는다.

**옵션 B: design-v2a(2장·4장·9장 8~23) → goal-2 → design-v2b(3장·9장 24~35) → goal-3.**
- 장점: 검토 단위가 작다. goal-2 결과를 보고 3장을 고칠 수 있다.
- 단점: 게이트 2회. 사용자가 "v2에 3장 추가"를 한 번에 요청한 것과 어긋남.
- 기각: 사용자 요청 우선. goal-2에서 드러난 수치 문제는 `fix-2:` + 문서 먼저 수정 절차로 처리.

**옵션 C: 문서 + 코드를 goal 하나로 (R2 전체).** 기각: 사용자가 goal-2/goal-3 분리를 요청, 파일 5개 초과·6회 규칙 위험, 사람 확인 단위가 너무 큼.

**점수 구현 분할(계획 수준 선택지)**
- (선택) 점등 +100과 점수 HUD는 goal-2, 클리어 보너스·실패 초기화(=새 판 시작 시 0)는 goal-3. 근거: 점등 점수는 점등 로직(goal-2)과 같은 함수에서만 바뀌고 goal-2에서 사람이 100씩 오르는 것을 볼 수 있다. 보너스는 "맵 클리어"와 "남은 시간 확정"에 의존하고 사람이 볼 수 있는 곳이 엔딩 화면(goal-3)이며, 초기화는 실패→타이틀→새 판이라는 goal-3 흐름에서만 관찰된다. 합치면 goal-2가 엔딩 점수를 못 보여 사람 확인이 반쪽이 된다.
- (대안) 점수 전체를 goal-3: goal-2에서 사람이 볼 점수 HUD가 없어 8~23번 중 점수 항목이 goal-3으로 밀리고 goal-3 파일·테스트가 커진다. 기각.
- (대안) 점수 전체를 goal-2: 클리어 보너스를 goal-2에서 구현하면 goal-2에는 엔딩 화면이 없어 보너스가 보이지 않는다(멈춘 플레이 화면에 점수만). 기각.

세부 선택지(갈매기 속도 번역, 기절 시 갈매기 처리, 틱 루프, 만료/클리어 판정, HUD 시간 표기)는 5절 결정표의 대안 열에 있다.

## 3. 범위 / 비범위 / 산출물

### 범위 (design-v2 문서 변경 목록, GAME_DESIGN.md만)

1. **머리말**: v1→v2, "이 문서는 v2다. v1에서 R1 범위를 채웠고 v2에서 R2 범위(2장 나머지 규칙·점수 표, 3장, 4장 갈매기·등불, 6장 사용처, 9장 8번~)를 채웠다"로 갱신. 표기 규칙에 "(R2 사용자 확정)"을 추가하고 "(에이전트 제안)"은 재사용.
2. **2장 규칙**: 3.1절 신규 행(R2 규칙 표)과 3.1b 점수 표를 "이동 규칙 표" 뒤에 추가. 수정은 두 곳만: (a) "벽 막힘" 행의 "갈매기 등 다른 충돌 규칙은 R2에서 채운다" 문구를 "갈매기 충돌은 `충돌 판정 시점` 행"으로 교체(R1 확정 결정 자체는 그대로), (b) "R1 임시 구현 표기" 문단 뒤에 "R2 임시 구현 표기" 문단 추가(3.2절)하고 "제한시간, 기절, 갈매기, ... R2에서 채운다" 줄 삭제.
3. **3장 화면 흐름 표** (3.3절): 타이틀·플레이·엔딩·실패 4행 + 화면 전환 keydown 소비 규칙 + R2 임시 문구.
4. **4장 오브젝트**: 머리 문장 "R1 범위는 곰, 바닥, 벽 3종이다..."를 "R1: 곰·바닥·벽, R2: 갈매기·등불"로 수정, 표에 갈매기·등불 행 추가, `L` 문단 교체, 스프라이트 격자 4종 추가(3.4절): 갈매기, 등불 꺼짐, 등불 켜짐, 곰 기절. 타이틀·엔딩·실패·HUD는 스프라이트가 아니라 글자(src/strings.js)이므로 새 격자 없음.
5. **5장**: 격자·글자 불변. "R1 범례 규칙" 중 "`L`은 ... 바닥으로 그린다(등불 그림·동작은 R2)"를 "`L`은 걸을 수 있고 바닥 타일 위에 등불 그림을 얹는다"로 교체.
6. **6장**: 열 이름 "R1 사용처" → "사용처 (R1·R2)", hex·인덱스·개수 불변, 사용처 문구 추가(3.5절). 인덱스 7 "예약" → "갈매기 몸·켜진 등불 중심 빛·기절 별·HUD·타이틀·엔딩·실패 글자".
7. **7장**: 여전히 R3. "R2 임시 문구는 3장 표에 적고 7장(R3)이 대체한다" 한 줄만 추가.
8. **9장**: 3.6절 구조 변경 + 4절 신규 8~35번.
9. **"아직 안 정한 것"**: R2 항목 전부 삭제(결정표로 이동). "R2 사용자 확인 대기"에는 아무것도 남기지 않는다(차단 항목 없음). R3 항목 그대로. "점수 저장·최고 점수(R3)"를 R3 목록에 한 줄 추가.
10. **10장 범위 밖**: 변경 없음(점수는 10장에 없고 리더보드는 계속 범위 밖).

### 비범위
레벨 2·3 격자·문구, 사운드(7장 R3), 점수 저장(localStorage)·최고 점수·리더보드, 8장 기술 스펙 확정, 갈매기 인접 판정, 일시정지, 도트 웹폰트, 모바일, 난이도, 인터뷰에서 다루지 않은 기능. 코드는 design-v2 커밋에 한 줄도 넣지 않는다. 사람 책임 산출물(저장소 파일 아님): 과제 제출용 스크린샷 4장(타이틀·플레이·클리어(엔딩)·실패)은 사람이 실제 플레이 화면에서 직접 찍는다. 계획·goal은 이 파일을 만들지 않고 fixture 스크린샷도 증거로 쓰지 않는다.

### 3.1 2장 신규 규칙 행 초안 (출처 표기 포함)

| 항목 | 값 | 출처 |
|---|---|---|
| 점등 | 곰이 `L` 칸 위에 서서 스페이스바를 누르면 그 등불이 켜진다. `L`이 아닌 칸에서는 아무 일도 없다. 이미 켜진 등불 칸에서 다시 눌러도 변화 없음(꺼지지 않고 개수·점수도 늘지 않음). 켜진 등불은 맵이 끝날 때까지 켜진 채다 | 점등 위치·키: 스펙 F5/R15. 재입력 무시: 에이전트 제안 |
| 스페이스바 입력 | keydown 한 번 = 한 번 시도, `event.repeat` 무시. 이동 쿨다운과 무관하다: 스페이스바는 쿨다운을 시작하지 않고 쿨다운에 막히지도 않는다. 스페이스바와 방향키의 기본 브라우저 동작(스크롤)은 `preventDefault()`로 막는다 | 에이전트 제안 (R1 쿨다운 결정 불변) |
| 제한시간 | 레벨마다 60 000 ms(60초). 플레이 화면에 들어가는 순간(타이틀에서 스페이스바 시작) 시작하고 다음 레벨에서 리셋된다. 경과 시간은 `performance.now()` 기준. 경과 > 60 000 ms이면 실패 | 60초·맵마다: 스펙 F3. 시작 시점·경계: 에이전트 제안 |

### 3.2 R2 임시 구현 표기 문단 초안
"R2 임시 구현: 페이지를 열면 `requestAnimationFrame` 루프가 매 프레임 `performance.now()`를 읽어 `tick`/`advance`로 상태를 진행하고 현재 화면을 그린다. 게임 상태는 시각을 인자로 받는 함수로만 바뀌므로 프레임 속도와 무관하다. keydown은 상태만 갱신하고(R1의 keydown 시 다시 그리기는 루프가 대체) 같은 `performance.now()` 시각을 쓴다. 틱 루프·입력·렌더링 방식은 8장(R3)이 정하며 R1·R2 임시 구현을 대체할 수 있다."

### 3.3 3장 화면 흐름 표 초안

| 화면 | 들어오는 조건 | 보이는 것 | 받는 입력 | 나가는 조건 |
|---|---|---|---|---|
| 타이틀 | 페이지를 열 때, 또는 엔딩·실패 화면에서 스페이스바 | `배경`색 전체, 가운데에 게임 이름 "등대지기 곰"(인덱스 5 글자)과 그 아래 "스페이스바로 시작"(인덱스 7). 맵·HUD 없음 | 스페이스바만. 방향키·엔터 등은 무시 | 스페이스바 → 플레이(1맵, 처음 상태, 이 순간 타이머 시작) |
| 플레이 | 타이틀에서 스페이스바 | 맵(바닥·벽·등불·갈매기·곰) 352×288 영역 + 아래 32 px HUD 띠 | 방향키, 스페이스바(점등). 그 외 키(엔터·Esc 포함)는 무시 | 등불 전부 점등(경과 ≤ 60 000 ms) → 맵 순서 규칙(R2는 엔딩), 경과 > 60 000 ms → 실패 |
| 엔딩 | 마지막 레벨 클리어 | `배경`색 전체, 가운데에 엔딩 문구 2줄 + `점수 n` + 안내 1줄 | 스페이스바만 | 스페이스바 → 타이틀 |
| 실패 | 플레이에서 시간 초과 | `배경`색 전체, 가운데에 실패 문구 1줄 + `점수 n` + 안내 1줄 | 스페이스바만 | 스페이스바 → 타이틀 |

화면 전환 keydown 소비 규칙(에이전트 제안): 한 번의 keydown은 정확히 하나의 효과만 낸다. 화면이 바뀐 keydown은 그 전환에 소비되어 새 화면에서 다시 처리하지 않는다. 스페이스바 한 번이 타이틀→플레이를 일으키면 같은 입력이 플레이에서 점등을 일으키지 않고, 엔딩·실패→타이틀을 일으키면 같은 입력이 타이틀→플레이를 일으키지 않는다(타이틀에서 시작하려면 키를 뗐다가 다시 눌러야 한다). 마지막 등불을 켜는 스페이스바는 점등+클리어를 일으키고 같은 입력이 엔딩에서 타이틀 전환을 일으키지 않는다. `event.repeat`는 모든 화면에서 무시한다. 입력 처리에서는 먼저 시간을 진행해 화면이 바뀌었으면(예: 만료로 실패) 그 입력은 새 화면에서 처리하지 않고 버린다(전환에 소비).

R2 임시 문구(7장 R3가 대체 가능), 모두 `src/strings.js` 한 곳(타이틀·HUD 라벨·실패·엔딩·안내 전부):
- 타이틀: "등대지기 곰" / "스페이스바로 시작" (R2 사용자 확정)
- 엔딩(스펙 F10, 원문 그대로): 「등대에 다시 불이 들어왔다. 곰은 아침까지 등불을 지킨다.」 폭 때문에 문장 사이 공백에서만 줄을 나눠 2줄로 보인다(글자 변경 금지). R2 임시: 레벨 1만 깬 결과에 뜨며 "3개 맵"과 의미가 어긋난다.
- 실패(에이전트 제안, 최소화): 「밤이 끝났다.」
- 안내(에이전트 제안): 「스페이스바로 처음 화면」
- 점수 줄(에이전트 제안): 「점수 n」
- HUD 라벨(에이전트 제안): 「등불」, 「점수」, 「남은 시간」
문구 색은 인덱스 7, 가운데 정렬. 전환 연출(페이드 등)은 없다: 상태가 바뀌면 다음 프레임에 바로 다른 화면이 보인다(에이전트 제안).

### 확인 범위 (신규 항목 중 화면으로 판정할 수 없어 테스트·diff 검토로 덮는 것)
- 정확한 60 000 ms·3 000 ms·300 ms 경계, 마지막 등불과 만료가 같은 시각일 때 클리어 우선(2장 "마지막 등불 vs 만료"), 보너스 계산의 정확한 값(남은 37.9초 → 370점, 0.4초 → 0점 등): 사람이 재지 않는다. 경계·계산 단위 테스트로 덮는다. 29번은 HUD 시간 표기(올림)와 보너스(내림)가 달라 근사(±1초 허용)로만 사람이 본다.
- 시드 20261113과 mulberry32 순서: 같은 시드 → 같은 난수열은 테스트, 시드를 쓰는 코드가 상수 한 곳만 쓰는지는 goal-2 diff 검토. 두 번 재시작해 갈매기 경로를 눈으로 비교하는 것은 300 ms 간격에서도 신뢰할 수 없어 수용 기준에 넣지 않았다.
- 인접 칸 비기절(스펙 F9)은 18번으로 사람이 볼 수 있다. 300 ms 간격이라 갈매기가 인접해 있는 시간이 약 0.3초 이내로 짧으므로 한 번에 안 보일 수 있고, 인접 상태에서 곰이 먼저 멀어지면 기절이 일어나지 않는 것도 함께 본다. 정확한 판정은 "거리 1이면 기절 아님" 단위 테스트로 덮는다(100 ms였다면 승격 곤란했던 항목이 300 ms에서 사람 확인 가능해졌지만 확률적이다).
- 곰이 갈매기를 피할 수 있는지(16번): 곰의 연타 속도(초당 최대 10칸)가 갈매기(초당 약 3.3칸)보다 빨라 사람이 눈으로 확인할 수 있다. 정확한 비율은 상수 테스트로 덮는다.
- 곰이 갈매기 칸으로 걸어 들어가는 경우와 갈매기가 곰 칸으로 들어오는 경우 둘 다 기절: 17번은 어느 쪽이든 발생만 본다. 두 경로 각각은 단위 테스트로 덮는다.
- 스페이스바가 이동 쿨다운에 영향이 없음, `preventDefault`, `event.repeat` 무시, rAF 루프가 `performance.now()` 하나만 쓰는지, 숫자(300·3 000·60 000·100·20261113·점수 100·10)가 `src/logic.js` 상수 한 곳에만 있고 다른 파일이 가져다 쓰는지: goal-2·goal-3 diff 검토(main.js).
- 타이틀에서 스페이스바 한 번이 점등과 전환을 동시에 일으키지 않는 규칙(소비 규칙): 레벨 1의 시작 칸은 `B` 칸이라 등불이 없어 사람이 점등 이중 발생을 눈으로 볼 수 없다. 화면 전환 단위 테스트(상태 불변·한 입력 한 효과)로 덮고, 사람은 34번(스페이스 한 번 = 타이틀까지만)과 26번(시작 시 타이머)으로 간접 확인한다.
- 팔레트 소속(코드 hex = 6장 hex)과 스프라이트 값 범위: R1과 같이 hex 텍스트는 사람이 diff에서 눈으로 비교, 값 범위(null 또는 0..7)는 테스트.
- 13번 "약 60초", 14번 시간 흐름: 사람이 초시계로 거칠게 본다(±1초 이내면 통과).

## 6. goal-2 / goal-3 정의

### 상태 형태 (goal-2가 정하고 goal-3이 그대로 전제)

레벨 상태(goal-2):
```
{ grid, bear: {col,row}, gull: {col,row},
  lit: [ {col,row}, ... ],
  score: number,                    // 한 판 누적 점수(점등분, goal-3에서 보너스 가산)
  status: 'playing' | 'cleared' | 'failed',
  startMs, endMs: number | null,    // cleared/failed 순간 기록, 남은 시간 고정에 사용
  nextGullMoveMs,
  stunUntilMs: number | null,       // null = 기절 아님
  rng: uint32 }                     // mulberry32 상태
```
게임 상태(goal-3 신설, 레벨 상태를 감쌈): `{ screen: 'title' | 'play' | 'ending' | 'fail', levelIndex, level }` (`level`은 title에서 null).
상수(전부 `src/logic.js` 한 곳, 값은 기획서 2장): `LEVEL_TIME_MS = 60000`, `STUN_MS = 3000`, `SEAGULL_MOVE_INTERVAL_MS = 300`, `RNG_SEED = 20261113`, `LAMP_SCORE = 100`, `CLEAR_BONUS_PER_SECOND = 10`, 기존 `MOVE_COOLDOWN_MS` 등. R1 `moveBear`는 `{...state, bear}`로 다른 필드를 보존하도록 바꾼다(R1 테스트는 `.bear`만 보므로 유지).

### goal-2: "등불·갈매기·60초 타이머·기절이 동작한다"

- **목표 한 문장**: 곰이 `L` 칸에서 스페이스바로 등불을 켜 점수(+100)가 오르고, 300 ms마다 다가오는 갈매기와 같은 칸이 되면 약 3초 기절하며, 60초 타이머가 HUD에 보인다(페이지를 열면 바로 플레이, 클리어·시간 초과는 멈춘 화면).
- **사람이 볼 완료 조건**: 9장 8~23번. 근거: 2장 "점등"·"스페이스바 입력"·"제한시간"·"마지막 등불 vs 만료"·"기절"·"기절 중"·"기절 시 갈매기"·"갈매기 배치/이동/이동 간격"·"난수"·"충돌 판정 시점"·"HUD" 행과 점수 표 "등불 점등"·"기절"·"점수 표시" 행, 4장 갈매기·등불·곰 기절 스프라이트, 5장 레벨 1 격자 `L`, 6장 사용처(인덱스 0~7).
- **건드릴 파일 (5개)**: `src/logic.js`, `src/main.js`, `src/sprites.js`, `src/strings.js`(신규, HUD 라벨만), `test/logic.test.js`(`test/index.js`가 이 파일 하나만 import하므로 테스트 파일을 늘리지 않는다). `src/levels.js`는 건드리지 않는다(`LEVEL1` 그대로).
- **순수 함수 시그니처 초안**:
  - `createState(grid, nowMs, startScore = 0, seed = RNG_SEED) → state` (곰 `B` 칸, 갈매기 `placeGull`, `lit: []`, `score: startScore`, `status: 'playing'`, `startMs = nowMs`, `endMs: null`, `nextGullMoveMs = nowMs + SEAGULL_MOVE_INTERVAL_MS`, `stunUntilMs: null`, `rng: seed`)
  - `lampCells(grid) → [{col,row}]`, `farthestFloorCell(grid, from) → {col,row}`, `nextRandom(rng) → { value, rng }`
  - `gullCandidates(grid, gull, bear) → [{col,row}]`, `stepGull(state) → state`
  - `advance(state, nowMs) → state` (기절 종료·갈매기 catch-up 이동·만료 선언. 사건은 시각순, 같은 시각이면 기절 종료가 먼저. `playing`이 아니면 그대로. 만료 시 `status: 'failed'`, `endMs = startMs + LEVEL_TIME_MS`)
  - `pressMove(state, key, nowMs) → state` (`advance` 후 `playing`이고 기절 아님이면 `moveBear` + 충돌 검사)

## 8. 위험·검증·6회 규칙·R1 충돌 지점

### 위험과 완화
- **R-1 (해소) 승리 확인 난이도**: 이전 초안은 갈매기 100 ms가 곰의 최고 속도와 같아 따돌릴 수 없다고 봤다. 사용자 확정 300 ms로 곰이 연타하면 갈매기보다 빠르다(곰 초당 최대 10칸, 갈매기 초당 약 3.3칸). 사람이 눈으로 피하는 것을 확인할 수 있다(9장 16번). 잔여 위험: 300 ms에서도 갈매기가 인접해 있는 시간이 짧아 18번을 한 번에 못 볼 수 있음 → "여러 번 시도" 문구와 단위 테스트로 보완.
- **R-2 (해소) 점수 표 오해석**: 사용자가 해석 A로 확정. 잔여 위험: 점수 숫자가 2장·HUD·테스트·goal에 분산 → 2장 점수 표가 단일 기준이고 숫자는 `src/logic.js` 상수 한 곳(`LAMP_SCORE`, `CLEAR_BONUS_PER_SECOND`), 테스트 기대값은 문서 예(370, 0, 670 등)에서 손으로.
- **R-3 (중간) 백그라운드 탭**: rAF 정지 중 `performance.now()`는 흐르므로 복귀 시 즉시 실패하거나 갈매기 catch-up 이동이 몰린다. 완화: R2는 일시정지를 만들지 않는다(기획서에 없음). 확인 범위·R3 후속에 기록.
- **R-4 (중간) 로직 크기**: goal-2가 logic.js·테스트를 크게 늘린다. 완화: 함수 단위로 나누고 시각 사건 처리(`advance`)를 단일 함수에 모음. 막히면 6회 규칙.
- **R-5 (낮음) 새 스프라이트 모양**: 초안은 사람이 v2 diff에서 모양을 고친다. 16×16·0~7 검사는 테스트.
- **R-6 (낮음) 글꼴**: monospace 한글 폭 차이로 가운데 정렬이 어긋날 수 있음. R2 임시이며 7장·R3에서 도트 폰트 결정.
- **R-7 (중간) 보너스 근사 확인**: HUD 올림 표기와 보너스 내림이 달라 사람이 29번을 정확히 확인할 수 없다(±1초 근사). 완화: 정확한 값은 단위 테스트, D29 대안(HUD 내림)을 사람이 v2 diff에서 선택할 수 있음.
- **R-8 (낮음) 엔딩 문구 의미 어긋남**: 레벨 1만 깬 결과에 "3개 맵" 엔딩 문구가 뜸. 완화: 사용자 확정, 문서에 "R2 임시" 표기, R3에서 레벨 3 클리어로 해소.
- **R-9 (낮음) goal-3 크기**: 5개 파일 상한에 정확히 걸림. 완화: 6절 분할 검토 문단(6번째 파일이 필요하면 멈추고 보고).

### R1 결정과의 충돌 지점 (R1 결정 자체는 불변)
1. keydown 때 다시 그리던 R1 임시 구현 → rAF 루프로 교체("R2 임시 구현" 표기, 8장 대체 가능). 벽 막힘·쿨다운·repeat 규칙은 불변.
2. `moveBear`가 `{grid, bear}`만 돌려줌 → `{...state, bear}`로 필드 보존(R1 테스트는 `.bear`만 확인).
3. `createState(grid)` → `createState(grid, nowMs, startScore, seed)` 확장.
4. `L` 칸 그리기 ↔ R1 9장 3번 "안쪽은 바닥": 바닥 위에 투명 등불을 얹어 해소(3번 문장 불변, D20).
5. 스페이스바 ↔ 쿨다운: 스페이스는 쿨다운을 시작하지 않고 막히지도 않음. R1 테스트 "방향키 외의 키는 이동하지 않는다"(스페이스 포함)는 그대로 유효(점등은 별도 함수).
6. 틱 루프(rAF) ↔ R1 "시간 기준은 `performance.now()` 하나": 콜백 인자 대신 콜백 안에서 `performance.now()` 호출로 유지.
7. 2장 "벽 막힘" 행의 "R2에서 채운다" 문구, 5장 "R1 범례 규칙" 문장, 6장 "예약" 문구, 9장 소제목·설명 문단은 문서만 수정(결정 불변).
8. R1 스프라이트 테스트(3종 순회)에 새 4종 추가. `test/index.js`가 `logic.test.js`만 import하므로 새 테스트 파일을 만들지 않는다.
9. 페이지를 열면 goal-2 시점에는 바로 플레이, goal-3부터 타이틀 → goal-2의 "페이지 열림 = 타이머 시작"이 goal-3에서 "스페이스바로 시작 = 타이머 시작"으로 바뀌는 점은 `createState` 호출 지점만 바뀌므로 로직 영향 없음(문서 3장에 명시).

### 검증 계획 (명령은 실행자가 사용; planner는 실행하지 않음)

(3) goal 중 기획서 숫자(점수 100·10, 300 ms, 60초, 3초, 시드)를 바꿔야 하면 코드가 아니라 문서를 먼저 고치고 사람에게 보고. (4) goal-2에서 상태 형태가 바뀌면 goal-3 정의 재계획. (5) goal-3에서 6번째 파일이 필요하면 멈추고 보고. (6) 점수 계산이 2장 점수 표와 어긋나면(R3 합계 일치 의무) 즉시 중단.

## 10. ADR 초안

- **Decision**: design-v2 한 번으로 2장 나머지 규칙·점수 표, 3장(타이틀·플레이·엔딩·실패), 4장 신규 오브젝트, 6장 사용처, 9장 8~35번을 채우고 사람 승인 뒤 goal-2(8~23번: 등불·갈매기·타이머·기절·점등 점수)와 goal-3(24~35번: 타이틀·승패·화면 전환·클리어 보너스·초기화)을 순서대로 구현한다. 갈매기는 300 ms 간격으로 mulberry32(시드 20261113, 레벨 시작마다 초기화)와 시각 인자 순수 함수로 접근하고, 틱은 R2 임시 rAF 루프로 한다. 점수는 2장 점수 표(100점/등불, 남은 시간 초(내림)×10)가 단일 기준이다.
- **Drivers**: 사람이 눈으로 판정 가능한 기준(네 화면 모두 실제 플레이로 도달), 사용자 확정값 준수·기획서 외 기능 금지(점수 저장·레벨 2·3 제외), goal ≤ 5파일·6회 규칙·결정적 테스트.
- **Alternatives considered**: 문서 2회 분할(옵션 B), 단일 goal(옵션 C), 점수를 한 goal에 몰기, setInterval 고정 틱, 기절 후 갈매기 무적 시간·밀어내기, 갈매기 간격 100/200 ms, 점수 B(수치 표)·C(표시 점수), 실패 시 즉시 자동 재시작, 엔터 재시작, 중간 "클리어" 화면, HUD 시간 내림 표기, 타이틀 없음.
- **Why chosen**: 사용자 요청과 R1 절차(design-vN → critic → 사람 승인 → goal-N → 사람 확인)에 일치하고 승인 게이트가 한 번이다. 시각 인자 함수는 프레임·탭 상태와 무관해 8장이 루프를 바꿔도 로직이 안 바뀐다. 기절 시 갈매기 이동은 새 숫자 없이 무한 재기절을 막는다. 점등 점수를 goal-2, 보너스·초기화를 goal-3에 둔 것은 사람이 각각 볼 수 있는 시점(점수 HUD/엔딩·실패 화면)과 일치한다. 스페이스 한 번 = 한 효과 규칙으로 화면 전환 이중 발생을 막는다.
- **Consequences**: v2 diff가 커서 critic·사람 검토 부담. 갈매기 300 ms로 승리 확인은 가능하지만 인접 비기절(18번)은 확률적이다. goal-2 로직에 `status`·`endMs`·`score` 판정이 들어가 goal-3 화면 전환의 전제가 된다. goal-3은 5개 파일 상한에 걸려 6번째 파일이 필요하면 replan. 엔딩 문구가 R2에서 "3개 맵"과 의미가 어긋난 채 임시 표시된다. HUD 올림/보너스 내림 불일치로 29번은 근사 확인. R2 임시 문구·글꼴·rAF는 R3(7장·8장)가 대체.
- **Follow-ups**: R3에서 레벨 2·3 격자와 `LEVELS` 확장(엔딩은 레벨 3 클리어), 레벨별 시드 초기화·점수 이월 확인, 점수 저장·최고 점수(localStorage, 2장 표와 합계 일치), 7장 문구·도트 폰트, 8장 루프·입력 정식화, 백그라운드 탭 처리 여부, `fix-N` 시 문서 선수정, 사람 책임 스크린샷 4장 제출.

## 11. 핸드오프
- design-v2 작성·goal-2·goal-3 구현: `executor` (goal 하나에 커밋 하나, 메시지 접두사 `design-v2:`/`goal-2:`/`goal-3:`). goal-3은 goal-2 사람 확인 뒤에만.
- design-v2 검토: `critic` (8절 점검 포인트), 시간·상태 모델·점수 단일 전환 지점이 의심되면 `architect`.
- 사용자 결정은 모두 확정됐으므로 승인 요청 시 에이전트 제안 목록(9절)만 제시. 사람 책임 산출물(스크린샷 4장)은 goal-3 사람 확인 때 사람이 직접 찍는다.
