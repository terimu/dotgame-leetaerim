# R2 계획 초안 (planner stage 1): GAME_DESIGN v1 → v2 문서 확장 + goal-2 + goal-3

상태: 초안. critic 검토와 사람 승인 전. 코드·GAME_DESIGN.md는 이 계획에서 수정하지 않았다(읽기 전용 역할).
순서: design-v2(GAME_DESIGN.md만, 커밋 `design-v2:`) → critic → 사람 승인 → goal-2(`goal-2:`) → 사람이 브라우저에서 9장 8~19번 확인 → goal-3(`goal-3:`) → 사람이 9장 20~26번 확인. goal-3은 goal-2 사람 확인 뒤에만 시작한다.

## 0. 요약

- R2 = 목표물(등불 점등)·위협(갈매기·기절)·타이머(goal-2) + 승패·화면 전환(goal-3). 레벨 2·3 격자, 사운드, 점수 저장, 10장 범위 밖 전부는 R3 이후이므로 넣지 않는다.
- design-v2는 2장 나머지 규칙, 3장 화면 흐름, 4장 갈매기·등불 오브젝트와 16×16 스프라이트, 6장 사용처 열, 9장 8번~26번(신규 19개, 총 26개)을 채운다. 6장 8색 hex·개수 불변.
- **design-v2를 승인받기 전에 사용자 확인이 필요한 항목 두 개가 있다**: MOI-1 "점수 표" 해석, MOI-2 "R2 승리 범위". 그리고 MOI-3 갈매기 이동 간격 숫자. 이 셋은 임의로 확정하지 않았고 기본값과 대안만 적었다.

## 1. RALPLAN-DR 요약

### Principles
1. 기획서(GAME_DESIGN.md)가 유일한 기준이다. 애매하면 문서를 먼저 고치고 사람이 본 뒤에 코드를 쓴다 (AGENTS.md).
2. goal 완료 = 사람이 브라우저에서 9장 번호를 확인. 테스트 통과·fixture 스크린샷은 증거가 아니다.
3. R1 확정 결정(벽 막힘=제자리, 이동 후 100 ms 쿨다운, keydown 1회=1칸, event.repeat 무시)은 불변. v2 diff에서 새로 정한 것만 "에이전트 제안"으로 표시해 사람이 본다.
4. 시간·난수는 모두 인자(`nowMs`, 시드 상태)로 받는 순수 함수로 만들어 결정적으로 테스트한다. 화면에서 관찰 불가능한 것은 수용 기준이 아니라 "확인 범위"에 두고 테스트·diff 검토로 덮는다.
5. 기획서·인터뷰 스펙에 없는 것은 만들지 않는다. 모르는 값은 만들지 않고 material-open-item으로 올린다.

### Decision Drivers (상위 3)
1. 사람이 브라우저에서 예/아니오로 판정 가능한 기준 (goal 크기·관찰 가능성).
2. 스펙 확정값 준수 + 기획서에 없는 기능 금지 (점수 표·승리 범위처럼 충돌하는 요청은 열린 항목으로).
3. goal 하나 ≤ 5개 파일·6회 규칙 안에서 끝낼 수 있는 분할, 그리고 결정적(시드·시간 인자) 테스트 가능성.

### Viable Options (계획 수준)

**옵션 A (선택): 문서 한 번(design-v2 전체) → goal-2 → goal-3.**
- 장점: 사용자 요청 그대로(v2에 2장·3장·9장 한 번에). 승인 게이트 1회. goal-3이 의존할 상태 형태를 문서·goal-2에서 먼저 굳힘.
- 단점: v2 diff가 커서 critic·사람 검토 부담이 큼. 3장(승패 화면)은 goal-3까지 코드로 검증되지 않는다.

**옵션 B: design-v2a(2장·4장·9장 8~19) → goal-2 → design-v2b(3장·9장 20~26) → goal-3.**
- 장점: 검토 단위가 작다. goal-2 결과를 보고 3장을 고칠 수 있다.
- 단점: 게이트 2회, 사용자가 "v2에 3장 추가"를 한 번에 요청한 것과 어긋남. 갈매기 속도처럼 goal-2에서 드러난 문제를 고치려면 어차피 fix-N 문서 수정이 필요.
- 기각: 사용자 요청 우선. 단 MOI-3 같은 수치는 goal-2 사람 확인에서 틀리면 `fix-2:` + 문서 먼저 수정 절차로 처리.

**옵션 C: 문서 + 코드를 goal 하나로 (R2 전체).** 기각: 사용자가 goal-2/goal-3 분리를 요청, 파일 5개 초과·6회 규칙 위험, 사람 확인 단위가 너무 큼.

세부 선택지(갈매기 속도 번역, 기절 시 갈매기 처리, 틱 루프, 만료/클리어 판정)는 3절 결정표의 대안 열에 있다.

## 3. 범위 / 비범위 / 산출물

### 범위 (design-v2 문서 변경 목록, GAME_DESIGN.md만)

1. **머리말**: v1→v2, "이 문서는 v2다. v1에서 R1 범위를 채웠고 v2에서 R2 범위(2장 나머지 규칙, 3장, 4장 갈매기·등불, 6장 사용처, 9장 8번~)를 채웠다"로 갱신. 표기 규칙에 "(R2 제안)"은 쓰지 않고 기존 "(에이전트 제안)" 재사용.
2. **2장 규칙**: 아래 신규 행(표는 "이동 규칙 표" 뒤 "R2 규칙 표"로 추가, 같은 3열 형식). 수정은 두 곳만: (a) "벽 막힘" 행의 "갈매기 등 다른 충돌 규칙은 R2에서 채운다" 문구를 "갈매기 충돌은 `충돌` 행"으로 교체(R1 확정 결정 자체는 그대로), (b) "R1 임시 구현 표기" 문단 뒤에 "R2 임시 구현 표기" 문단 추가 및 "제한시간, 기절, ... R2에서 채운다" 줄 삭제.
3. **3장 화면 흐름 표** (3.3절).
4. **4장 오브젝트**: 머리 문장 "R1 범위는..."을 "R1: 곰·바닥·벽, R2: 갈매기·등불"로 수정, 표에 갈매기·등불 행 추가, `L` 문단 교체, 스프라이트 격자 4종 추가(3.4절): 갈매기, 등불 꺼짐, 등불 켜짐, 곰 기절.
5. **5장**: 격자·글자 불변. "R1 범례 규칙" 중 "`L`은 ... 바닥으로 그린다(등불 그림·동작은 R2)"를 "`L`은 걸을 수 있고 바닥 타일 위에 등불 그림을 얹는다"로 교체.
6. **6장**: 열 이름 "R1 사용처" → "사용처 (R1·R2)", hex·인덱스·개수 불변, 사용처 문구 추가(3.5절). 인덱스 7 "예약" → "갈매기 몸·켜진 등불 빛·기절 별·HUD 글자".
7. **7장**: 여전히 R3. 단 "R2 임시 문구는 3장 표에 적고 7장(R3)이 대체한다" 한 줄만 추가.
8. **9장**: 3.6절 + 4절.
9. **"아직 안 정한 것"**: R2 항목 전부 삭제(결정표로 이동). 대신 "R2 사용자 확인 대기"에 MOI-1~MOI-5를 남기고, 해결되면 지운다. R3 항목은 그대로.
10. **10장 범위 밖**: 변경 없음.

### 비범위
레벨 2·3 격자, 사운드(7장 R3), 점수 저장, 8장 기술 스펙 확정, 갈매기 인접 판정, 시작/타이틀 화면, 일시정지, 도트 웹폰트, 모바일, 난이도, 인터뷰에서 다루지 않은 기능. 코드는 design-v2 커밋에 한 줄도 넣지 않는다.

### 3.1 2장 신규 규칙 행 초안 (출처 표기 포함)

| 항목 | 값 | 출처 |
|---|---|---|
| 점등 | 곰이 `L` 칸 위에 서서 스페이스바를 누르면 그 등불이 켜진다. `L`이 아닌 칸에서는 아무 일도 없다. 이미 켜진 등불 칸에서 다시 눌러도 변화 없음(꺼지지 않고 개수도 늘지 않음). 켜진 등불은 맵이 끝날 때까지 켜진 채다 | 점등 위치·키: 스펙 F5/R15. 재입력 무시: 에이전트 제안 |
| 스페이스바 입력 | keydown 한 번 = 한 번 시도, `event.repeat` 무시. 이동 쿨다운과 무관하다: 스페이스바는 쿨다운을 시작하지 않고 쿨다운에 막히지도 않는다. 스페이스바와 방향키의 기본 브라우저 동작(스크롤)은 `preventDefault()`로 막는다 | 에이전트 제안 |
| 제한시간 | 레벨마다 60 000 ms(60초). 레벨이 시작될 때(페이지 열림·재시작) 시작하고 다음 레벨에서 리셋. 경과 시간은 `performance.now()` 기준. 경과 > 60 000 ms이면 실패 | 60초·맵마다: 스펙 F3. 시작 시점·경계: 에이전트 제안 |
| 마지막 등불 vs 만료 | 만료는 경과 > 60 000 ms일 때만 선언한다. 마지막 등불 점등 입력이 처리되는 시각이 경과 ≤ 60 000 ms이면 맵 클리어가 이긴다. 입력 처리 때는 먼저 시간을 그 시각까지 진행한 뒤(갈매기 이동·만료 선언 포함) 입력을 적용한다 | 에이전트 제안 (R1 쿨다운 "경계 포함"과 같은 방향) |
| 기절 | 곰과 갈매기가 같은 칸이 되는 순간 곰은 3 000 ms(약 3초) 기절. 기절이 끝나면(경과 ≥ 3 000 ms) 같은 칸에서 부활. 인접 칸은 기절하지 않음 | 3초·제자리 부활·같은 칸만: 스펙 F1/F9. 경계 포함: 에이전트 제안 |
| 기절 중 | 방향키·스페이스바 입력을 모두 무시한다. 타이머는 계속 줄어든다. 갈매기는 아래 `기절 시 갈매기` 규칙대로 멈춰 있다 | 에이전트 제안 (스펙은 "기절 중 조작 규칙"을 비목표로 둠) |
| 기절 시 갈매기 | 기절이 시작되는 순간 갈매기는 곰 칸에서 사라지고 `갈매기 배치` 규칙의 칸으로 옮겨져 곰이 부활할 때까지 움직이지 않는다. 부활 후 첫 이동은 부활 시각 + 이동 간격 | 에이전트 제안 (무한 재기절 방지) |
| 갈매기 배치 | 갈매기를 놓는 칸 = 곰이 있는 칸에서 맨해튼 거리가 가장 먼 바닥(`#`가 아닌) 칸. 거리가 같으면 위쪽 행, 그다음 왼쪽 열 우선. 레벨 시작 때는 곰 시작 칸 기준(레벨 1 = 오른쪽 아래 안쪽 구석 칸), 기절 때는 기절한 곰 칸 기준. 좌표는 문서에 쓰지 않고 격자에서 계산 | 에이전트 제안 |
| 갈매기 이동 | `갈매기 이동 간격`(ms)마다 한 칸. 이동 후보 = 위·아래·왼쪽·오른쪽 이웃 중 `#`가 아니고 맵 안이며 곰까지 맨해튼 거리가 현재보다 줄어드는 칸. 후보 중 하나를 난수로 고른다(후보 순서 위·아래·왼쪽·오른쪽). 후보가 없으면 제자리. 이동 한 번에 난수를 정확히 한 번 쓴다(후보 수와 무관). 갈매기는 벽을 통과하지 않는다. 등불 칸 위에 서도 등불에는 아무 영향이 없고 갈매기가 위에 그려진다 | 접근·무작위·1칸: 스펙 F6. 후보 규칙·벽·등불 위: 에이전트 제안 |
| 갈매기 이동 간격 | **100 ms** (= 곰이 연속 이동할 수 있는 가장 빠른 속도, 쿨다운 100 ms). 상수 `SEAGULL_MOVE_INTERVAL_MS`를 `src/logic.js` 한 곳에 둠 | "곰과 같은 속도": 스펙 F6/R16. 숫자 100: 에이전트 제안 (**MOI-3**) |
| 난수 | mulberry32(고정 시드 20261113). 상태는 32비트 정수 하나(`a`): `a = (a + 0x6D2B79F5) \| 0; t = Math.imul(a ^ (a >>> 15), 1 \| a); t = (t + Math.imul(t ^ (t >>> 7), 61 \| t)) ^ t; 값 = ((t ^ (t >>> 14)) >>> 0) / 4294967296`. 시드는 레벨이 시작될 때마다(페이지 열림, 실패·엔딩 뒤 재시작, R3의 다음 레벨) 20261113으로 되돌린다. design-v2 작성자가 시드 20261113의 첫 3개 값을 node 한 줄로 계산해 이 행에 적는다(테스트 기대값의 출처, 코드는 커밋 안 함) | 고정 시드: 스펙 R11, 값 20261113은 v1 기록. 알고리즘·초기화 시점: 에이전트 제안 |
| 충돌 판정 시점 | 곰이 이동한 직후와 갈매기가 이동한 직후, 각각 같은 칸인지 검사한다. 곰이 갈매기 칸으로 들어가든 갈매기가 곰 칸으로 들어가든 같다. 곰·갈매기 이동은 서로 다른 시각의 사건이므로 칸을 "교차"해 지나가는 경우는 없다(곰이 갈매기 칸으로 들어가는 순간 기절) | 스펙 F9. 시점 정의: 에이전트 제안 |
| 맵 순서·승리·실패 | 등불을 전부 켜면 맵 클리어. 레벨 N 클리어 → N+1(바로, 연출 없음). 마지막 레벨 클리어 → 엔딩. 시간 초과 → 실패. 실패·엔딩 뒤 엔터 → 1맵부터 처음 상태로 다시 시작(등불 전부 꺼짐, 곰 시작 칸, 타이머 60초, 갈매기 배치, 시드 초기화). R2에서 레벨은 레벨 1뿐이므로 마지막 레벨 = 레벨 1 (임시, **MOI-2**) | 순서·1맵부터 재시작·엔딩: 스펙 F4/F10. 엔터·즉시 전환: 에이전트 제안 |

### 3.2 R2 임시 구현 표기 문단 초안
"R2 임시 구현: 페이지를 열면 `requestAnimationFrame` 루프가 매 프레임 `performance.now()`를 읽어 `advance(state, nowMs)`로 상태를 진행하고 그린다. 게임 상태는 시각을 인자로 받는 함수로만 바뀌므로 프레임 속도와 무관하다. keydown은 상태만 갱신하고(R1의 keydown 시 다시 그리기는 루프가 대체) 같은 `performance.now()` 시각을 쓴다. 틱 루프·입력·렌더링 방식은 8장(R3)이 정하며 R1·R2 임시 구현을 대체할 수 있다."

### 확인 범위 (신규 항목, 화면으로는 판정할 수 없어 테스트·diff 검토로 덮음)
- 정확한 60 000 ms·3 000 ms 경계, 마지막 등불과 만료가 같은 시각일 때 클리어 우선(2장 "마지막 등불 vs 만료"): 사람이 재지 않는다. 경계 단위 테스트로 덮는다.
- 시드 20261113과 mulberry32 순서: 같은 시드 → 같은 난수열은 테스트로, 시드를 쓰는 코드가 그 상수 하나뿐인지는 goal-2 diff 검토로 덮는다. 사람이 두 번 재시작해 갈매기 경로를 눈으로 비교하는 것은 100 ms 간격에서는 신뢰할 수 없어 수용 기준에 넣지 않았다.
- 인접 칸 비기절(스펙 F9): 100 ms 간격에서는 눈으로 확인하기 어렵다. "인접(거리 1)이면 기절하지 않는다" 단위 테스트로 덮는다. 갈매기 이동 간격이 사람이 볼 수 있을 만큼 느려지면(MOI-3 변경) 수용 기준으로 승격한다.
- 곰이 갈매기 칸으로 걸어 들어가는 경우와 갈매기가 곰 칸으로 들어오는 경우 둘 다 기절: 15번은 어느 쪽이든 기절 발생만 본다. 두 경로 각각은 단위 테스트로 덮는다.
- 스페이스바가 이동 쿨다운에 영향이 없음, `preventDefault`, `event.repeat` 무시, rAF 루프가 `performance.now()` 하나만 쓰는지: goal-2 diff 검토(main.js)로 덮는다. 스페이스바 직후 방향키가 바로 먹는지는 100 ms라 사람이 판정하기 어렵다.
- 갈매기 이동 간격·기절 시간·시드·제한시간 숫자가 `src/logic.js` 상수 한 곳에만 있고 다른 파일이 가져다 쓰는지: diff 검토.
- 팔레트 소속(코드 hex = 6장 hex, 스프라이트 값이 0~7): hex 텍스트 눈 비교는 R1과 같은 방식, 스프라이트 값 범위는 테스트.
- 1초당 1씩 줄어드는 정확도(13번): 사람이 "약 60초"를 초시계로 거칠게 본다. ±1초 안이면 통과.

## 6. goal-2 / goal-3 정의

### 상태 형태 (goal-2가 정하고 goal-3이 그대로 전제)
```
{ grid, levelIndex,
  bear: {col,row}, gull: {col,row},
  lit: [ {col,row}, ... ],          // 켜진 등불 칸
  status: 'playing' | 'cleared' | 'failed',
  startMs, nextGullMoveMs,
  stunUntilMs: number | null,        // null = 기절 아님
  rng: uint32 }                      // mulberry32 상태
```
상수(전부 `src/logic.js` 한 곳, 기획서 2장 수치): `LEVEL_TIME_MS = 60000`, `STUN_MS = 3000`, `SEAGULL_MOVE_INTERVAL_MS = 100`(MOI-3), `RNG_SEED = 20261113`, 기존 `MOVE_COOLDOWN_MS` 등. R1 `moveBear`는 `{...state, bear}`로 다른 필드를 보존하도록 바꾼다(R1 테스트는 `.bear`만 보므로 유지).

### goal-2: "등불·갈매기·60초 타이머·기절이 동작한다"

- **사람이 볼 완료 조건**: 9장 8~19번. 근거: 2장 "점등"·"스페이스바 입력"·"제한시간"·"기절"·"기절 중"·"기절 시 갈매기"·"갈매기 배치/이동/이동 간격"·"난수"·"충돌 판정 시점"·"HUD" 행, 4장 갈매기·등불·곰 기절 스프라이트, 5장 레벨 1 격자 `L`, 6장 사용처(인덱스 0~7).
- **건드릴 파일 (5개)**: `src/logic.js`, `src/main.js`, `src/sprites.js`, `src/strings.js`(신규, HUD 라벨), `test/logic.test.js`. 필요하면 `src/levels.js`는 건드리지 않는다(`LEVEL1`은 그대로).
- **순수 함수 시그니처 초안**:
  - `createState(grid, nowMs, seed = RNG_SEED) → state` (곰 `B` 칸, 갈매기 `placeGull(grid, bear)`, `lit: []`, `status: 'playing'`, `startMs = nowMs`, `nextGullMoveMs = nowMs + SEAGULL_MOVE_INTERVAL_MS`, `stunUntilMs: null`, `rng: seed`)
  - `lampCells(grid) → [{col,row}]`, `farthestFloorCell(grid, from) → {col,row}`
  - `nextRandom(rng) → { value, rng }` (mulberry32)
  - `gullCandidates(grid, gull, bear) → [{col,row}]`, `stepGull(state) → state`
  - `advance(state, nowMs) → state` (stun 종료·갈매기 이동 catch-up·만료 선언, 사건은 시각순, 같은 시각이면 stun 종료가 먼저, `playing`이 아니면 그대로)
  - `pressMove(state, key, nowMs) → state` (= `advance` 후 `playing`이고 기절 아님이면 `moveBear` + 충돌 검사)
  - `pressLight(state, nowMs) → state` (= `advance` 후 `playing`이고 기절 아님이고 곰이 켜지지 않은 `L` 위면 점등, 전부 켜지면 `status: 'cleared'`)
  - `remainingSeconds(state, nowMs) → 0..60`, `litCount(state)`, `lampTotal(state)`
  - main.js 쿨다운 배선: 방향키 `pressMove` 결과로 곰이 실제로 움직였을 때만 `lastMoveMs` 갱신(R1과 동일), 스페이스는 `lastMoveMs`를 건드리지 않음.
- **테스트 목록 (기대값은 기획서 숫자·5장 격자에서 손으로, 코드 되풀이 금지)**:
  1. 상수 대조: 60 000, 3 000, 100(MOI-3 확정값), 20261113 (2장).
  2. 레벨 1 등불 3개이고 위치는 격자에서 손으로 읽은 (2,2), (6,2), (3,4) (5장).
  3. `(2,2)`에서 점등 → `lit`에 (2,2). `.` 칸에서는 변화 없음. 이미 켜진 칸에서 재점등 → 개수 불변 (2장 "점등").
  4. 3번째 점등 → `status 'cleared'`. 경과 정확히 60 000 ms의 점등 = 클리어, 60 001 ms = `failed`(2장 "마지막 등불 vs 만료"). `advance`: 60 000 ms → `playing`, 60 001 ms → `failed`.
  5. `remainingSeconds`: 경과 0→60, 1→60, 1 000→59, 59 001→1, 60 000→0 (2장 HUD).
  6. `farthestFloorCell`: 곰 (1,1) → (7,5) (유일 최대), 곰 (4,3) → 동률 네 구석 중 위·왼쪽 (1,1) (2장 "갈매기 배치").
  7. mulberry32: 같은 시드 → 같은 열, 값 ∈ [0,1), 시드 20261113의 첫 3개 값 = 2장 "난수" 행에 design-v2 작성자가 적은 값.
  8. `gullCandidates`: 갈매기 (7,5), 곰 (1,1) → 후보는 {(7,4),(6,5)}만. 모서리·벽 근처에서 후보에 `#`·맵 밖 없음. 곰과 같은 칸이면 후보 없음(제자리).
  9. 갈매기 이동 타이밍: 99 ms 진행 → 제자리, 100 ms → 한 칸, 500 ms → 다섯 칸(catch-up). 매 이동마다 난수 1회(이동 후 `rng`가 한 번 진행됨).
  10. 곰 고정 시 갈매기가 (1,1)에 10칸 안에 도달해 기절(거리 10). 인접(거리 1) 상태에서는 기절 아님 (스펙 F9).
  11. 곰이 갈매기 칸으로 들어가면 기절, 갈매기가 곰 칸으로 들어가도 기절.
  12. 기절: `stunUntilMs = t + 3000`. +2999 ms에 `pressMove`·`pressLight` 무시, +3000 ms에 허용(경계 포함). 기절 중 갈매기 정지, 갈매기는 `farthestFloorCell`로 이동, 부활 직후 같은 칸 아님. 기절 중에도 `advance`로 60 001 ms에 `failed`.

## 8. 위험·검증·6회 규칙·R1 충돌 지점

### 위험과 완화
- **R-1 (높음) 승리 확인 난이도**: 갈매기 100 ms는 곰의 최고 속도와 같고 항상 접근하므로 곰이 따돌릴 수 없다. 기절 한 번에 3초 + 갈매기가 먼 곳에서 오는 데 최대 약 1초 → 60초에 약 15번 기절 주기, 등불 3개를 켜는 데 필요한 연속 시간이 짧을 수 있다. 완화: MOI-3를 사람이 design-v2 승인 때 정한다. 대안 값(200/300 ms)은 문서 한 줄만 바꿔도 된다. goal-2 사람 확인에서 20번을 못 보면 `fix-2:`(문서 먼저)로 간격을 조정한다.
- **R-2 (중간) 점수 표 오해석**: MOI-1이 풀리기 전 design-v2를 승인하면 문서·goal이 틀어질 수 있다. 완화: 승인 조건에 MOI-1 해결을 넣는다. A를 고르면 9장·2장·HUD·goal-2/3 정의를 다시 쓰므로 critic 재검토 필요.
- **R-3 (중간) 백그라운드 탭**: rAF 정지 중 `performance.now()`는 흐르므로 복귀 시 즉시 실패하거나 갈매기 catch-up 이동이 몰린다. 완화: R2는 일시정지를 만들지 않는다(기획서에 없음). "확인 범위"·R3 후속에 기록.
- **R-4 (중간) 로직 크기**: goal-2가 logic.js·테스트를 크게 늘린다. 완화: 함수 단위로 나누고 시각 사건 처리(`advance`)를 단일 함수에 모음. 막히면 6회 규칙.
- **R-5 (낮음) 새 스프라이트 모양**: 초안은 사람이 v2 diff에서 모양을 고친다. 16×16·인덱스 0~7 검사는 테스트.
- **R-6 (낮음) 글꼴**: monospace 한글 폭이 달라 가운데 정렬이 어긋날 수 있음. R2 임시이며 7장·R3에서 도트 폰트 결정.

### R1 결정과의 충돌 지점
1. keydown 때 다시 그리던 R1 임시 구현 → rAF 루프로 교체("R2 임시 구현" 표기, 8장 대체 가능). 벽 막힘·쿨다운·repeat 규칙은 불변.
2. `moveBear`가 `{grid, bear}`만 돌려줌 → `{...state, bear}`로 필드 보존(R1 테스트는 `.bear`만 확인).
3. `createState(grid)` → `createState(grid, nowMs, seed)` 확장.
4. `L` 칸 그리기 ↔ R1 9장 3번 "안쪽은 바닥": 투명 등불 스프라이트를 바닥 위에 얹어 해소(3번 불변).
5. 스페이스바 ↔ 쿨다운: 스페이스는 이동 쿨다운과 무관. R1 테스트 "방향키 외의 키는 이동하지 않는다"(스페이스 포함)는 그대로 유효(점등은 별도 함수).
6. 5장 "R1 범례 규칙" 문장, 2장 "벽 막힘" 행의 "R2에서 채운다" 문구, 6장 "예약" 문구는 문서만 수정(결정 불변).
7. rAF 콜백 인자 대신 콜백 안에서 `performance.now()` 호출(R1이 정한 "시간 기준은 performance.now() 하나" 유지).
8. R1 스프라이트 테스트(3종 순회)는 새 4종을 추가해야 함.

### 검증 계획 (명령은 실행자가 사용; planner는 실행하지 않음)
- design-v2: `git diff --stat`가 `GAME_DESIGN.md` 하나만 보이는지, 9장 1~7번 줄과 6장 hex 8줄이 diff에 `-` 줄로 나타나지 않는지(`git diff -U0 GAME_DESIGN.md`로 눈 확인), `src/`·`test/` 변경 없음. 커밋 메시지 `design-v2:`.
- critic 점검 포인트: 9장 26개 번호 연속·1~7 불변, 모든 신규 항목에 근거 장, 관찰 불가 항목이 확인 범위에 있는지, 6장 8색, 범위 밖(레벨 2·3·사운드·점수 저장) 미포함, MOI 항목 명시.
- goal-2/goal-3: `node --test test/` 통과는 필요조건이지 완료가 아니다. 완료는 사람의 9장 번호 확인. diff 검토 항목은 확인 범위 목록.
- 6회 규칙: 한 goal에서 같은 시도 6회 초과 반복 금지. 막히면 멈추고 어디서 막혔는지(어느 9장 번호·어떤 함수) 보고 → ralplan.
- Escalation/Risk Gate: (1) MOI-1~MOI-3이 풀리기 전 design-v2 승인 금지, (2) goal-2 사람 확인 전 goal-3 시작 금지, (3) goal 중 기획서 숫자를 바꿔야 하면 코드가 아니라 문서를 먼저 고치고 사람에게 보고, (4) goal-2에서 상태 형태가 바뀌면 goal-3 정의 재계획.

## 10. ADR 초안

- **Decision**: design-v2 한 번으로 2장 나머지 규칙·3장·4장 신규 오브젝트·6장 사용처·9장 8~26번을 채우고 사람 승인 뒤 goal-2(8~19번, 등불·갈매기·타이머·기절)와 goal-3(20~26번, 승패·화면 전환)을 순서대로 구현한다. 갈매기 접근은 mulberry32(시드 20261113, 레벨 시작마다 초기화)와 시각 인자 순수 함수로, 틱은 R2 임시 rAF 루프로 한다.
- **Drivers**: 사람이 눈으로 판정 가능한 기준, 스펙 확정값 준수·기획서 외 기능 금지, goal ≤ 5파일·6회 규칙·결정적 테스트.
- **Alternatives considered**: 문서 2회 분할(옵션 B), 단일 goal(옵션 C), setInterval 고정 틱, 기절 후 갈매기 무적 시간·밀어내기, 갈매기 이동 간격 200/300 ms, 점수 규칙 표(A)·표시 점수(C), 실패 시 즉시 자동 재시작.
- **Why chosen**: 사용자 요청과 R1 절차에 일치하고 승인 게이트가 한 번이다. 시각 인자 함수는 프레임·탭 상태와 무관해 8장이 루프를 바꿔도 로직이 안 바뀐다. 기절 시 갈매기 이동은 새 숫자 없이 무한 재기절을 막는다.
- **Consequences**: v2 diff가 커서 critic·사람 검토 부담. MOI-1~3 해결 전 승인 불가. 갈매기가 100 ms면 난이도·승리 확인이 어려울 수 있어 사람이 정해야 함. goal-2 로직에 `status` 판정이 들어가 goal-3 화면 전환의 전제가 됨. R2 임시 문구·글꼴·rAF는 R3(7장·8장)가 대체.
- **Follow-ups**: R3에서 레벨 2·3 격자와 `LEVELS` 확장, 레벨별 시드 초기화 확인, 7장 문구·도트 폰트, 8장 루프·입력 정식화, 백그라운드 탭 처리 여부, 점수 저장(R3, MOI-1 결과에 따라), `fix-N` 시 문서 선수정.
